# ADR 0008: Session code format (5 × 31-symbol alphabet), lifecycle, tokens and anti-guessing controls

- **Status:** Accepted (2026-10-17, confirmed by the project owner)
- **Component(s):** `server`, `protocol`, `web`, `quest`, `slicer` (code display/QR)
- **Related:** `docs/architecture.md` (threat model — canonical; code lifecycle), `docs/protocol.md`
  (`create_session`, `resume`, `join`, error codes), `docs/requirements.md` (UX: code readable from 2 m),
  `docs/security.md` (negative tests), ADR 0006 (fragment-only URL), ADR 0007 (redeploy drops sessions)

## Context

Non-negotiable requirements (`prompts/00-goal.md`): a 5-character session code, readable and easy to retype,
alphabet without confusable characters (`0/O`, `1/I/L`), generated by the relay, unique among active sessions,
with expiry and heartbeat refresh; protection against guessing (rate limiting, lock-out after N attempts); codes
and tokens never in URL paths or logs. Verified facts (`docs/research/relay.md`, `web.md`):

- Alphabet `23456789ABCDEFGHJKMNPQRSTUVWXYZ` = 8 digits + 23 letters = **31 symbols** (counted; `0 1 O I L`
  removed). 31^5 = **28,629,151** codes ≈ **24.77 bits**. (Crockford base32 would give 32^5 = 33.5 M.)
- Guessing math: the chance that `k` random attempts hit one of `S` live sessions ≈ `1 − (1 − S/N)^k`:
  S = 100, k = 1,000 → 0.35 %; k = 10,000 → 3.4 %. From one IP at 10 attempts/min, the expected time to hit any of
  100 live sessions is N/S/10 min ≈ 20 days (architect's computation; `relay.md` originally said "~2.4 months", corrected to ~20 days on 2026-10-17;
  either way the controls below are what bounds the attack, not entropy). Scanning half the space takes 994 days at 10/min.
- `@fastify/rate-limit` 11.2.1: `max`, `timeWindow`, `ban` (count of 429s before 403), per-IP key via
  `request.ip` (needs `trustProxy: true`; Railway edge setting `X-Forwarded-For` is `[TODO verify]`); `onRequest`
  hook runs before the WebSocket upgrade. Because the code travels *inside* the WebSocket, join attempts need an
  in-process per-IP counter too.
- RFC 3986 §3.5: fragments never reach the server. Railway edge logs record the request path (query string
  `[TODO verify]`) → codes only in `/j#ABCDE` and WebSocket message bodies.
- `crypto.randomInt(31)` per symbol gives uniform, CSPRNG-backed symbols; collision probability per draw with
  1,000 live sessions is 3.5e-5 → retry on collision. Resume tokens: `crypto.randomBytes(16)` (128 bits),
  stored as SHA-256, grace period while the publisher is offline.
- Redeploys/crashes empty the registry (ADR 0007); `create_session { preferredCode, resumeToken }` lets the
  publisher keep its code when it is free.

## Decision

1. **Format:** 5 symbols from `23456789ABCDEFGHJKMNPQRSTUVWXYZ`, uppercase, displayed as `ABCDE` (optionally
   grouped `AB CDE` for reading aloud; the canonical form has no separators).
2. **Generation (relay only):** `crypto.randomInt(0, 31)` per symbol; reject and redraw if the code is held by any
   *active or grace-period* session or is in the recently-expired quarantine set (10 min, prevents a new session
   from inheriting viewers of an old one). `preferredCode` from a publisher resume is honoured only when free or when
   the `resumeToken` matches.
3. **Lifecycle:** unused code (publisher connected, no viewer ever joined) expires after 30 min; session TTL 30 min
   of inactivity (publisher heartbeat every 15 s refreshes; viewers' heartbeats do not keep a publisher-less session
   alive); hard cap 12 h; publisher **grace period 120 s** after disconnect (viewers see "publisher reconnecting"),
   after which the session ends and viewers receive close 4xxx `session_ended`.
4. **Tokens:** publisher **resume token** = 128-bit random, base64url, returned once in `session_created`, stored
   hashed (SHA-256) by the relay, used in `resume { code, token }`; **viewer token** = per-connection 128-bit
   random returned in `joined`, used for `/api/scene/:version` (`Authorization: Bearer`) and for reconnect without
   re-rate-limiting within 120 s. Tokens are never persisted, never logged, never in URLs.
5. **Transport of the code:** only as the URL **fragment** (`https://<host>/j#ABCDE`, QR payload) and inside the
   first WebSocket message (`join { code }`). The viewer calls `history.replaceState(null, '', '/j')` after reading
   it. The relay never accepts a code in a path, query string, header or cookie (such requests 404/400 without echo).
6. **Anti-guessing:** (a) HTTP: `@fastify/rate-limit` on the upgrade route, 60/min/IP, `trustProxy: true`;
   (b) WebSocket join: in-process per-IP limiter **10 join attempts/min**, **ban for 15 min after 20 failed joins**
   (sliding window, HMAC-hashed IP keys); after 3 failures on one socket the relay closes it with 4xxx
   `too_many_attempts`; (c) **global failed-join alarm**: > 1,000 failed joins/hour logs a `warn` with counts only
   and tightens the per-IP limit to 3/min until the hour resets; operators may switch to 6 symbols by config;
   (d) uniform `invalid_code` error for unknown, expired and full-but-wrong codes, with constant-time comparison.
7. **Input normalisation (viewer and Quest keypad):** trim whitespace and `-`/space separators, map lowercase →
   uppercase, then **reject** any character outside the alphabet **with a targeted hint**: for `0`/`O` → "codes
   never contain 0 or O — check that character"; for `1`/`I`/`L` → "codes never contain 1, I or L". No
   confusable *mapping* is performed, because both members of each confusable pair are absent from the alphabet:
   there is no valid symbol a typed `O` could have meant, so mapping would only hide a reading error. The Quest
   keypad shows only the 31 valid keys, which makes the rule self-evident.

## Consequences

**Positive**

- 24.8 bits of code space with per-IP and global limits makes untargeted guessing uneconomic (days per hit for a
  single IP, and hits land on random sessions, not a chosen one); session TTLs shrink the live set `S`.
- Codes are human-friendly (no confusables, 5 symbols readable from 2 m), tokens carry the real entropy.
- Fragment + body transport guarantees Railway edge logs and `Referer` headers never contain a code.
- Publisher resume keeps the on-screen code valid across network blips and relay redeploys.

**Negative**

- Per-IP limiting is a cost raiser, not a wall (attackers rotate IPs); hence the global alarm and the 6-symbol
  switch. Classroom NAT means 20 students share one IP → the per-IP join limit (10/min) must not block legitimate
  joins: a correct join does not count as a failure, and the viewer token lets reconnects bypass the limiter.
- Rejecting (not mapping) confusables adds one more "try again" for users who misread `O` for `D` or `Q`; mitigated
  by the hint and by QR/deep link as the primary path.
- In-memory limiter and ban state reset on redeploy (single replica, ADR 0007).
- 128-bit resume tokens must be kept in Slicer memory for the session; if Slicer is restarted the code is lost and a
  new one must be shared.

**Follow-ups**

- `protocol`: encode the alphabet as a JSON Schema `pattern` (`^[23456789ABCDEFGHJKMNPQRSTUVWXYZ]{5}$`), error
  codes `invalid_code`, `session_full`, `too_many_attempts`, `session_ended`, token fields.
- `server`: generator with collision retry + quarantine set; limiters; constant-time compare; unit tests for
  alphabet, uniqueness, TTL transitions. `qa`: brute-force and NAT-classroom scenarios in `docs/security.md`.
- `web`/`quest`: normaliser with the two hints; keypad with 31 keys; `replaceState`.
- `slicer`: large monospace code + QR with `https://<host>/j#<CODE>`, resume token held in memory only.
- `deploy`: verify `X-Forwarded-For` on the first deploy (prerequisite for per-IP limits).

## Alternatives considered

- **6 decimal digits** (10^6 = 20 bits). Rejected: fewer codes than 31^5, longer to type, and still contains
  `0`/`1`; kept only as the *emergency* 6-symbol (31^6 ≈ 887 M) switch in the same alphabet.
- **Word codes (e.g. 3 dictionary words).** Rejected: hard to type on a Quest keypad and on phones in a second
  language; QR payloads longer; localisation issues for a Polish/English audience.
- **QR-only join (no typed code).** Rejected: headsets cannot scan a screen easily, projector QR codes are often
  unreadable from the back of a room, and the goal mandates a typed code; QR is the primary *convenience* path.
- **Mapping confusables (`O`→`0`, `I`/`L`→`1`).** Rejected: the targets are not in the alphabet either, so mapping
  cannot produce a valid code; a hint is more honest and keeps the alphabet rule simple.
- **Code in URL path (`/join/ABCDE`) or query.** Rejected: appears in Railway edge logs, browser history and
  `Referer` (CLAUDE.md rule 6).
