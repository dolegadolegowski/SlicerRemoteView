# Plan — `deploy` (GitHub Actions CI, Docker in CI, Railway IaC, release automation)

| | |
|---|---|
| Component | `deploy` |
| Directories owned | `.github/` (workflows, dependabot, templates, scripts), `.railway/` (`railway.ts`), `docs/deploy.md`; the relay `Dockerfile` itself is owned by `server` (`SRV-20`, `relay-server/Dockerfile`) and only *built* here |

| Prompt | `prompts/06-deploy-ci.md` |

**How to read this plan.** Tasks are ordered by dependency; `⚑` = critical path for M0/M1 CI. Workflows must
work when a component directory does not exist yet (`detect` job outputs, never `hashFiles` in `jobs.<id>.if`).
Nothing here deploys by itself: `railway config apply` runs only on `main` with a secret, and the first deploy is
a manual, documented step (`docs/deploy.md`). CI must pass for PRs from forks without secrets.
