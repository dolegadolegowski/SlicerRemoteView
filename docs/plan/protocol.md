**How to read this plan.** Tasks are ordered by dependency; take the first `todo` whose dependencies are `done`
(or `[stub allowed]`). `⚑` marks the critical path from `docs/plan/00-overview.md` §4. Every task includes its
tests; `docs/protocol.md` is authoritative when this table and the prose disagree.

## Follow-ups / later milestones

- Protocol v1.1 (M4 candidates, ADR required): `scene.camera`, `viewer.command`, per-node GLB in
  `scene.nodeAdded`, `KHR_draco_mesh_compression` (§8.5, §14). Each needs schemas, fixtures and a
  `docs(protocol)` commit first.
- `gltf-validator` availability as an npm package `[TODO verify]`; fallback is the Dart binary downloaded in CI
  (DEP-02) or a reduced in-house check.
- Optional: fuzz corpus for `parseEnvelope` (feeds QA-11's viewer fuzzing).
- Consider publishing `shared/py` to PyPI only if the Extension Index review asks for an installable dependency;
  vendoring stays the default (ADR 0007).

## Manual verification needed

- None of this plan requires Slicer, Unity or a device. PRO-17's compile check needs `dotnet` or Unity; when
  neither is in the sandbox, the compile is verified by QST-03 in Unity (`docs/testing/quest.md` §2).
- `gltf-validator` must be runnable offline in CI; if it needs a download, DEP-02 documents the step.
