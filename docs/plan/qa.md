| | |
|---|---|

**How to read this plan.** `qa` never fixes component code and never edits other plans: findings go to
`docs/testing/reports/<date>-qa-<n>.md`. Tasks are ordered by dependency; `⚑` = critical path for the M1 release
check. `tests/` has its own `package.json` (it is not a root workspace) — commands run as `npm --prefix tests run
<script>`. Everything here runs against `relay-server` + `fake-slicer` + `web-viewer` built from `main`; device
and Slicer scenarios are manual and live in `docs/testing/<component>.md`.

## Follow-ups / later milestones

- Staging relay on Railway for load tests across the real edge (egress cost — coordinate with `deploy`, NFR-34).
- Fuzzing of `parseEnvelope` on the relay (JSON fuzz corpus) once `fast-check` or a corpus exists (`protocol`

- Accessibility audit (axe) across all viewer screens beyond the contrast check in WEB-17.

## Manual verification needed

- Real devices: iPhone (iOS ≥ 16.4 and 15.x), Android Chrome, Quest 2, Quest 3/3S — scenarios in
  `docs/testing/web.md` and `docs/testing/quest.md`; `qa` records results, `web`/`quest` own the steps.

  `fake-slicer` for everything automated.
- Measurements over a real 4G connection (NFR-01) and a classroom Wi-Fi with 20 phones (NFR-05, ADR 0008 NAT case).
- Railway-side checks (logs retention, alerts, EU region) with the user's account (`docs/deploy.md` §4, §6).
