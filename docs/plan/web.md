# Plan — `web` (web-viewer: mobile browser 3D viewer, WebXR mode for Quest Browser)

| | |
|---|---|
| Component | `web` |
| Directories owned | `web-viewer/` |

| Stack | Vite 8, TypeScript, three.js r186 (`three@0.186.1`, pinned), `GLTFLoader`, `OrbitControls`, WebXR (`XRButton`, `XRControllerModelFactory`, `XRHandModelFactory`), vitest, Playwright (iPhone 15 / Pixel 7 descriptors), no UI framework |
| Contract | `docs/protocol.md` v1.0 ("§n" below) |
| Design | `docs/architecture.md` §7 (viewer pipeline), §8 (T6, T8, T10); ADR 0001, 0002, 0003 (M3a), 0005, 0006, 0008 |
| Prompt | `prompts/03-web-viewer.md`; research `docs/research/web.md` |

**How to read this plan.** Tasks are ordered by dependency; `⚑` = critical path (`docs/plan/00-overview.md` §4).
`src/protocol/` (connection, reassembly, versions) has no DOM or three.js imports and is unit-tested on fixtures
from `shared/`; `src/render/` wraps three.js; `src/ui/` is DOM. Until `relay-server` is on `main`, E2E runs
against the `fake-slicer` relay stub (`PRO-13`) — mark `[stub: SRV-xx]`. iOS Safari behaviour is verified on a
device per `docs/testing/web.md`; Playwright WebKit is not Safari.

## Follow-ups / later milestones

- WEB-07 review (low): rules for the Slicer exporter (SLC) to raise in `docs/testing/reports/` when its export task
  starts: (1) pad strided views to whole strides — three.js `GLTFLoader` reads `count × byteStride` bytes (from
  `floor(byteOffset / stride) × stride`), more than the glTF minimum `(count − 1) × stride + elementSize`, so a view
  ending exactly at the last element passes `glb-validate.ts` but fails to parse; (2) skip entities with no triangles
  (an empty segment cannot be a valid accessor, `count ≥ 1`, and a T node without an M is refused — one such segment
  would make the whole snapshot `snapshotInvalid`); (3) only POSITION + NORMAL per primitive, one mesh/material per
  node, no `extensions` objects. Chunk alignment, `extensions`, attribute and single-use rules are stricter than
  plain glTF on purpose (§7.1/§7.2); relax only together with a protocol change. WEB-07 is ≈ 730 source + 1,500 test
  lines, well above the ~300-line guideline: most of it is the hostile-input validator and its tests (three review
  rounds), which could not be split without leaving the viewer exploitable in between.
- WEB-06 review (low): `scene-loader.ts` is ~330 lines and `scene-http.ts` ~250 — above the ~300-line task guideline
  together; the split keeps each file reviewable. Content-encoded responses skip the `Content-Length` check — confirm
  whether SRV-11 / the Railway edge ever compresses `model/gltf-binary` (`[TODO verify]`). Whether a token rejoin
  (`viewer.join{sessionId, viewerToken}`) issues a new token and invalidates the old one is not stated in §5.2
  (`[TODO verify]` against SRV-15). `main.ts` does not wire `loader.on("failed")` yet — WEB-10 must leave the busy
  state and show a retry. iOS: the stall watchdog timer may fire right after a backgrounded tab resumes, before queued
  `read()` results run — add "background during download, then resume" to `docs/testing/web.md` §iPhone Safari (WEB-10)
  and, if it restarts healthy downloads, ignore a stall within one tick of `visibilitychange → visible`.

- WEB-05 review (low): one throwing event handler in `snapshot-stream.ts` `emit` (and in `connection.ts`) stops the
  handlers after it and propagates into `handleFrame`; wrap each handler call in try/catch (log the event name only)
  when the app wiring grows (WEB-10).

- WEB-04 review (low): any frame counts as liveness, so a dead uplink with a live downlink is only caught by the relay's
  60 s WS-ping terminate — consider "dead after 3 pings without a `pong`"; a throttled background tab can fire the pong
  timer before the queued message — WEB-14's `visibilitychange` liveness check must cover it; handler loops in
  `connection.ts` have no try/catch; a drift test deriving `SHAPES` from `shared/schema/*.schema.json` would be cheap.
