# Research A1: 3D Slicer extension for SlicerRemoteView

Status: research note (architect), 2026-10-17. Component: `slicer` (`slicer-plugin/`).
Every claim carries a source and the version it was checked against; unverified items are marked `[TODO verify]`.
Sources are listed at the end and referenced as `[Sn]`.

## Key findings for the design

- **Target platform:** Slicer stable is **5.12.4** (tag `v5.12.4`, 2026-09-10); `main` is 5.13.0 (preview). Stable 5.12.4 ships
  **Python 3.12.10**, **VTK 9.6** (Slicer fork, commit `slicer-v9.6.2-2026-05-15`), **Qt 5.15 or Qt 6.8**. Support 5.12.x only;
  do not rely on `slicer.packaging` for 5.10 (absent there). [S1][S2][S3][S4]
- **Module shape:** a Python-only *scripted loadable module* (`ScriptedLoadableModule` + `Widget` + `Logic` + `Test`),
  generated by the Extension Wizard; no C++ build needed. CMakeLists uses `slicerMacroBuildScriptedModule(... WITH_GENERIC_TESTS)`
  and `slicer_add_python_unittest(SCRIPT <Module>.py)`. [S5][S6][S7]
- **Extension Index:** submit a `<ExtensionName>.json` (required: `category`, `scm_url`) by PR to `Slicer/ExtensionsIndex`.
  Tier-1 checklist includes a LICENSE.txt, README, icon + screenshot, and **"Does not send any information anywhere without user
  consent (explicit opt-in is required)"** — directly relevant to a streaming extension: connect only after an explicit user action. [S8][S9]
- **Meshes:** model polydata via `modelNode.GetPolyData()` (node-local coordinates); segment meshes via
  `vtkSlicerSegmentationsModuleLogic.GetSegmentClosedSurfaceRepresentation(segNode, segmentId, polyData, applyParentTransform)`
  (static, creates nothing — call `segNode.CreateClosedSurfaceRepresentation()` first). Segment closed surfaces are already in
  the segmentation node's (RAS) frame; only the **parent transform** remains to be applied. [S10][S11][S12]
- **Appearance:** model color/opacity/visibility from `vtkMRMLDisplayNode` (`GetColor`, `GetOpacity`, `GetVisibility3D`,
  `GetVisibility(viewNodeID)`); segment color via `segDisplayNode.GetSegmentColor(id)` (honours override colour, falls back to
  `segment.GetColor()`), `GetSegmentOpacity3D(id)`, `GetSegmentVisibility3D(id)`, plus whole-segmentation `Opacity3D`. [S13][S14][S15]
- **Transforms:** `node.GetParentTransformNode()`; `transformNode.GetMatrixTransformToWorld(vtkMatrix4x4)` returns 0 if non-linear
  → in that case bake geometry with `vtkTransformPolyDataFilter` + `GetTransformToWorld(vtkGeneralTransform)` and re-send the mesh.
  Send linear transforms as a 4x4 matrix in the protocol; never call `HardenTransform()` on the user's nodes. [S16][S17]
- **Events:** scene `NodeAddedEvent`/`NodeRemovedEvent` (call data = node, needs `@vtk.calldata_type(vtk.VTK_OBJECT)`),
  displayable `DisplayModifiedEvent` (any display node changed), `vtkMRMLModelNode.MeshModifiedEvent`,
  `vtkMRMLTransformableNode.TransformModifiedEvent`, segmentation `vtkSegmentation.SegmentAdded/SegmentRemoved/SegmentModified/
  RepresentationModified` (re-invoked on the node, call data = segment ID `char*`). Skip work while `scene.IsImporting()`/`IsBatchProcessing()`
  and flush on `EndImportEvent`/`EndBatchProcessEvent`. Use `slicer.util.VTKObservationMixin`. [S18][S19][S20][S21][S22]
- **Threading rule:** only the main (Qt) thread may touch Qt/MRML/VTK. Network IO goes to a `threading.Thread` doing pure-Python
  socket work; results cross back through `queue.Queue` polled by a `qt.QTimer` on the main thread (the pattern Slicer itself uses in
  `slicer.util._startAsyncProcessHandling`). Pure-Python threads only progress when the main thread releases the GIL, so the
  main-thread timer must also call `time.sleep(0.001)`-style yields or keep the timer short-period. **asyncio does not integrate with
  Slicer's Qt loop** (core devs: no general way; WebServer uses `qt.QSocketNotifier` instead). [S23][S24][S25][S26][S27]
- **WebSocket library:** use **`websockets` ≥ 14 with its `websockets.sync.client`** (threading implementation, added in 11.0;
  14.x–15.x require Python ≥ 3.9, 16.x ≥ 3.10, 17.x ≥ 3.11 → Slicer's 3.12 is fine) or `websocket-client` (`WebSocketApp.run_forever`
  in a thread). Install on first use with `slicer.packaging.pip_ensure(...)` (prompts the user; skipped in testing mode), never at import. [S28][S29][S30][S31]
- **glTF export:** `vtk.vtkGLTFExporter` (available in Slicer, used by SlicerOpenAnatomy) writes **JSON `.gltf` only, never `.glb`**,
  exports the *render window* scene (actors), writes `baseColorFactor` RGBA from actor diffuse colour + opacity but **never sets
  `alphaMode: BLEND`**, and writes VTK coordinates as-is (no Y-up conversion, mm). Recommendation: write GLB ourselves with numpy +
  `struct` (small, dependency-free, full control over node IDs, materials, units). `vtkGLTFWriter` (IO/Geometry) writes `.glb` when the
  filename ends in `.glb` but is CityGML/multiblock-oriented — `[TODO verify]` that it is wrapped in Slicer's VTK build. [S32][S33][S34][S35]
- **Coordinates:** RAS (mm, right-handed) → glTF (m, right-handed, +Y up, +Z forward). Mapping per vertex: `x_gltf = R·0.001`,
  `y_gltf = S·0.001`, `z_gltf = -A·0.001` (determinant +1, so winding is preserved). SlicerOpenAnatomy uses the equivalent root matrix. [S36][S35]
- **Decimation:** `vtkQuadricDecimation` (edge collapse, better shape, target not guaranteed under topological constraints) vs
  `vtkDecimatePro` (vertex removal, `PreserveTopologyOn` limits reduction; guarantees the target only when topology may change).
  Slicer's own segmentation conversion uses `vtkDecimatePro` with `PreserveTopologyOn`, `SetMaximumError(1)`; Surface Toolbox defaults to
  reduction 0.8 via the `Decimation` CLI (FastQuadric / DecimatePro). Both need triangles (`vtkTriangleFilter`) and new normals
  (`vtkPolyDataNormals`) afterwards. [S37][S38][S39][S40]
- **QR code:** `segno` (pure Python, no dependencies, PNG/SVG serializers built in, `make(...).save(buf, kind="png", scale=N, border=B)`)
  is the safest in Slicer's environment; `qrcode` needs `pypng` (or Pillow via `qrcode[pil]`). Render via `qt.QPixmap.loadFromData(bytes)`
  (PythonQt converts `bytes` → `QByteArray` for by-value parameters) or, as a fallback, write a temp PNG and `qt.QPixmap(path)`. [S41][S42][S43]
- **Startup/limits:** no pip installs, heavy imports or network calls at module import or in the module constructor (slows startup for
  every user; Extension Index policy). Defer to `slicer.app.connect("startupCompleted()", fn)` or first use. Slicer recommends ≥8 GB RAM and
  ~10× data size in memory; segmentation meshes can reach hundreds of MB (STL/OBJ exports of ~100 MB reported) → decimation and
  per-node chunking are mandatory. [S44][S45][S46]

## 2. Access to MRML nodes

### Model nodes [S10][S13]

- `vtkMRMLModelNode.GetPolyData()` → `vtkPolyData` ("Return the input mesh if it is a polydata"); `GetMesh()` → `vtkPointSet`.
  Geometry is stored in the node's local frame; `GetBounds()` = untransformed, `GetRASBounds()` = with transforms [S10].
- Display: `modelNode.GetDisplayNode()` / `GetModelDisplayNode()`; `vtkMRMLDisplayNode`: `GetColor()` (3 doubles 0–1), `GetOpacity()`,
  `GetVisibility()` (int), `GetVisibility3D()`, `GetVisibility(viewNodeID)` (also checks subject-hierarchy folder visibility and view list),
  `GetViewNodeIDs()` (empty = all views), `GetScalarVisibility()`, `GetActiveScalarName()`, `GetColorNode()`, representation enum
  `PointsRepresentation / WireframeRepresentation / SurfaceRepresentation` [S13].
- A displayable node can have several display nodes (`GetNumberOfDisplayNodes()`, `GetNthDisplayNode(n)`); `GetDisplayVisibility()`
  returns 0/1/2 (none/all/some visible) [S18]. For v1 export the first display node is enough; `[TODO decide]` whether to honour
  per-view visibility (view node IDs) or only `Visibility && Visibility3D`.
- numpy access: `slicer.util.arrayFromModelPoints(modelNode)` (zero-copy, VTK-owned memory), `arrayFromModelPolyIds` (legacy
  `n,i0,i1,i2` layout), `arrayFromModelPointData(modelNode, name)` [S50]. For GLB indices prefer VTK 9 `vtkCellArray` offsets +
  connectivity: `polys.GetConnectivityArray()`, `polys.GetOffsetsArray()`, `IsHomogeneous()` (all triangles → connectivity array is directly
  the index buffer) [S51]; convert with `vtk.util.numpy_support.vtk_to_numpy`.

### Segmentation nodes [S11][S12][S14][S15][S19]

- Segments: `seg = segNode.GetSegmentation()`; `seg.GetNumberOfSegments()`, `seg.GetNthSegmentID(i)`, `seg.GetSegmentIDs()`,
  `seg.GetSegment(id)`; `segment.GetColor()` (stored colour), `segment.GetName()`; source representation name via
  `seg.GetSourceRepresentationName()` (binary labelmap in most clinical scenes) [S19].
- Closed surface: `segNode.CreateClosedSurfaceRepresentation()` (all segments; conversion may take seconds for large volumes), then
  either `segNode.GetClosedSurfaceRepresentation(segmentId, outPolyData)` (DeepCopy, **no parent transform**) [S11][S12] or the static
  `slicer.vtkSlicerSegmentationsModuleLogic.GetSegmentClosedSurfaceRepresentation(segNode, segmentId, outPolyData, applyParentTransform=True)`
  which applies `GetTransformToWorld` via `vtkTransformPolyDataFilter` when requested [S20].
  `GetClosedSurfaceInternalRepresentation(id)` gives the live internal polydata — read-only use only.
- The conversion rule (`vtkBinaryLabelmapToClosedSurfaceConversionRule`) transforms the mesh "from labelmap IJK to world coordinate
  system" of the segmentation (its reference image geometry), so the polydata is in the segmentation node's RAS frame before any parent
  transform [S39].
- Display (`vtkMRMLSegmentationDisplayNode`): `GetSegmentColor(id)` → `vtkVector3d`, uses override colour if set (components ≥ 0) else
  `segment->GetColor` [S14][S15]; `GetSegmentOpacity3D(id)`, `GetSegmentVisibility(id)` (overall), `GetSegmentVisibility3D(id)`,
  `GetVisibleSegmentIDs()`, whole-segmentation `GetOpacity3D()` (multiply), `GetPreferredDisplayRepresentationName3D()`.
  Slicer's own "export segments to models" sets model colour = `segment->GetColor()` and model opacity = `GetSegmentOpacity3D(id)` [S20] —
  mirror that: effective opacity = `Opacity3D(global) × SegmentOpacity3D` `[TODO verify the displayable manager multiplies both]`.
- Conversion parameters (defaults): decimation factor `0.0`, smoothing factor `0.5`, compute surface normals `1`, conversion method `0`
  (`vtkDiscreteFlyingEdges3D`; `1` = `vtkSurfaceNets3D`), joint smoothing `0` [S39]. Users may have changed them; our exporter should not.

### Transforms [S16][S17][S21]

- `vtkMRMLTransformableNode.GetParentTransformNode()`, `GetTransformNodeID()`, `HardenTransform()` ("Apply the associated transform to
  the transformable node") — hardening mutates the user's data; never do it for export [S21].
- `vtkMRMLTransformNode.GetMatrixTransformToWorld(vtkMatrix4x4)` → "Returns 0 if the transform is not linear"; `IsTransformToWorldLinear()`;
  `GetTransformToWorld(vtkGeneralTransform)` for the general (possibly non-linear, concatenated) case; static
  `GetTransformBetweenNodes(src, dst, vtkGeneralTransform)` with `None` = world [S17].
- Script-repository pattern for world-space polydata: `vtkMRMLTransformNode.GetTransformBetweenNodes(modelNode.GetParentTransformNode(), None, t)`
  + `vtkTransformPolyDataFilter` [S16].
- Protocol consequence: per node send `matrixToWorld` (16 floats, RAS mm) when linear; when non-linear (warping transforms) send baked
  geometry with identity matrix and flag `baked: true`.

### Node IDs and scene lifecycle [S22]

- `AddNode()` generates a unique ID such as `vtkMRMLModelNode1`; IDs are unique within a scene. On loading a scene file an ID can be
  remapped (`GetChangedID()`, `UpdateNodeReferences()`), so IDs are **stable while the scene is open, not across saves/reloads**.
  Use `node.GetID()` as the protocol `nodeId` for a session; a new session is started when the scene is closed (`EndCloseEvent`).
- Segments have no MRML ID; use `"<segmentationNodeID>/<segmentID>"` (segment IDs are unique within a segmentation [S52]).
- Scene states: `IsImporting()`, `IsBatchProcessing()`, `IsClosing()`; events `StartImportEvent/EndImportEvent`,
  `StartBatchProcessEvent/EndBatchProcessEvent`, `StartCloseEvent/EndCloseEvent`, `NodeAboutToBeAddedEvent/NodeAddedEvent`,
  `NodeAboutToBeRemovedEvent/NodeRemovedEvent` [S22].

## 3. Observing changes and threading

### Events to observe

| What | Observe | Event | Call data |
|---|---|---|---|
| Node added/removed | `slicer.mrmlScene` | `vtkMRMLScene.NodeAddedEvent`, `NodeRemovedEvent` | node (`@vtk.calldata_type(vtk.VTK_OBJECT)`) [S16][S22] |
| Appearance (colour/opacity/visibility, any display node) | displayable node | `vtkMRMLDisplayableNode.DisplayModifiedEvent` (17000) | display node `[TODO verify call data]` [S18] |
| Display node directly | display node | `vtk.vtkCommand.ModifiedEvent` | — [S13] |
| Mesh changed | model node | `vtkMRMLModelNode.MeshModifiedEvent` (17001) | — [S10] |
| Parent transform (or its matrix) changed | transformable node | `vtkMRMLTransformableNode.TransformModifiedEvent` (15000) | — [S21] |
| Segment set / content | segmentation node | `vtkSegmentation.SegmentAdded/SegmentRemoved/SegmentModified/RepresentationModified/SourceRepresentationModified/SegmentsOrderModified` (re-invoked on the node via `InvokeCustomModifiedEvent`) | segment ID as `char*` for segment events [S12][S19] |
| Segment display props | segmentation display node | `ModifiedEvent` (only when a value actually changed) | — [S15] |
| Scene load/close | `slicer.mrmlScene` | `EndImportEvent`, `EndBatchProcessEvent`, `StartCloseEvent`, `EndCloseEvent` | — [S22] |

Use `slicer.util.VTKObservationMixin`: `addObserver(obj, event, method, group="none", priority=0.0)`, `removeObserver(obj, event, method)`,
`removeObservers(method=None)`, `hasObserver(...)` [S50]; call `removeObservers()` in `cleanup()` [S6].
`vtkMRMLSegmentationNode` does **not** emit `DisplayModifiedEvent` itself when segments change; observe the segmentation events above and
the display node separately [S12].

### Debounce pattern (main thread)

Each event handler only marks the node dirty (`self._dirty[nodeId] |= flags`) and (re)starts a single-shot `qt.QTimer`
(e.g. 100–250 ms); the timer callback drains the dirty set, builds protocol messages and hands them to the sender. The script repository
documents `qt.QTimer.singleShot(0, fn)` to defer until the current event finishes and `qt.QTimer.singleShot(3000, fn)` for polling loops,
and recommends timers over `time.sleep` loops [S16]. Mesh-level changes (`MeshModifiedEvent`, `RepresentationModified`) should use a longer
debounce (≈500 ms–1 s) because segment editing fires them continuously.

### Threading constraints

- Core-developer guidance: worker threads are fine for computation, but **only the main thread may modify MRML nodes, call Qt or fire
  MRML events**; a worker that touched nodes crashed Slicer [S23][S24]. VTK does not release the GIL in Slicer by default; Slicer is not
  built with `VTK_PYTHON_FULL_THREADSAFE` (not in `External_VTK.cmake`) [S4][S24].
- Pure-Python threads only run when the main thread releases the GIL; a user observed a worker that progressed only on mouse movement.
  Lasso's recommendation: have a `QTimer` on the main thread call `time.sleep()` regularly (as SimpleFilters does) [S24]. Socket `recv`
  with a timeout releases the GIL, so the network thread itself is fine; the *main-thread* polling timer is what keeps the worker alive
  during idle GUI.
- Slicer's own pattern (`slicer.util._startAsyncProcessHandling`): "Background thread: read stdout and put lines into queue" +
  "Main thread: poll queue and process available output" via QTimer [S50]. Adopt the same for the WebSocket client.
- asyncio: "I haven't seen a general purpose way to use our Qt event loop with asyncio" (Pieper); Slicer WebServer integrates sockets via
  `qt.QSocketNotifier(fileno, qt.QSocketNotifier.Read)` + `.connect("activated(int)", cb)` [S25][S26][S27]. A `QSocketNotifier`-driven
  WebSocket client would need a non-blocking WebSocket protocol implementation (e.g. `wsproto`/`websockets` Sans-I/O) — feasible but more
  code than the thread+queue design; keep as alternative.
- PythonQt: signals connect to Python callables with `obj.connect("signal(type)", callable)` or `obj.signal.connect(callable)` [S16][S27][S43];
  invoking Qt from a non-GUI thread is undefined — do not emit from the worker.

Recommended architecture (adapter, testable without Slicer, rule 10 of CLAUDE.md): `SceneWatcher` (main thread; observers + debounce →
dirty set), `Exporter` (main thread; VTK → GLB bytes), `RelayClient` (worker thread; `websockets.sync` connection, outbound `queue.Queue`,
inbound `queue.Queue`, reconnect with backoff), `Pump` (main-thread `qt.QTimer` 50–100 ms: drains inbound queue, pushes outbound messages,
yields with a tiny sleep). GLB encoding of large meshes can be moved to the worker thread **only** if it operates on numpy copies
(`np.array(..., copy=True)`) made on the main thread.

## 4. Export to glTF/GLB

### `vtkGLTFExporter` (VTK 9.6/9.7 docs and source) [S32][S33][S35]

- Subclass of `vtkExporter`; exports what the **render window** renders: iterates renderers (skips `!ren->GetDraw()`), actors
  (skips `!GetVisibility()`), takes `findPolyData(mapper->GetInputDataObject(0,0))`, applies `actor->GetMatrix()` as node `matrix`.
- Output: `WriteData()` streams JSON to `FileName`; `WriteToString()`/`WriteToStream()` exist. **No GLB** (no magic/`glb` handling in source).
  `InlineDataOn()` embeds buffers as base64 (single self-contained `.gltf`); otherwise external `.bin`.
- Material: `baseColorFactor = [diffuse rgb, opacity]`, PBR metallic/roughness from property (or derived from specular); **no `alphaMode`
  written** → semi-transparent actors render opaque in viewers unless the JSON is patched (SlicerOpenAnatomy does exactly this:
  `material['alphaMode'] = 'BLEND'` when alpha < 1) [S35]. Per-vertex colours via `mapper->MapScalars` → `COLOR_0`; textures via PNG.
- Options: `SaveNormal` (point array named `NORMAL`), `SaveBatchId`, `SaveNaNValues`; coordinates written as-is (VTK/RAS, mm).
- Limitations for us: needs a renderer+actors (either Slicer's 3D view — includes slice planes, markups, etc. — or a private offscreen
  `vtkRenderWindow` as OpenAnatomy does), base64 inflates size by 33 %, no stable node IDs, no per-node incremental export.

### `vtkGLTFWriter` [S34]

- Input is a `vtkMultiBlockDataSet` ("as produced by the CityGML reader"); `Binary` is set from the `.glb` extension; `SaveActivePointColor`
  (COLOR_0), `SaveNormal`, textures through field data. Not a scene exporter; material handling is building-oriented.
  `[TODO verify]` that IO/Geometry Python wrapping includes `vtk.vtkGLTFWriter` in Slicer 5.12 (`External_VTK.cmake` does not disable it).

### Alternatives

- **Custom GLB writer (recommended):** one `.glb` per node (or per segment) containing one mesh with one primitive (TRIANGLES),
  `POSITION` (float32, with required `min`/`max`), optional `NORMAL`, `indices` (uint32 or uint16), one material with
  `pbrMetallicRoughness.baseColorFactor` and `alphaMode: "BLEND"` when opacity < 1. GLB container (spec §4) [S36]:
  12-byte header (`magic 0x46546C67`, `version 2`, `length`), chunk 0 JSON (`0x4E4F534A`, padded with `0x20`), chunk 1 BIN
  (`0x004E4942`, padded with `0x00`), little-endian, every chunk start/end 4-byte aligned; vertex attributes 4-byte aligned, `byteStride`
  multiple of 4. Implementation: numpy for arrays, `struct.pack("<III", ...)` for header, `json.dumps(separators=(",", ":"))`. ~150 lines,
  no dependencies, pure function → unit-testable outside Slicer with a validator (`gltf-validator` in CI, `[TODO]` in `tools/`).
- `pygltflib` (pure Python, writes GLB) and `trimesh` (needs numpy; `trimesh.exchange.gltf`) are usable via `pip_ensure`, but add install
  prompts and failure modes for little gain `[TODO verify versions if chosen]`.

### Coordinate systems and units [S36][S35]

- glTF: "right-handed", "+Y as up, +Z as forward, and -X as right", "units for all linear distances are meters", node `matrix` column-major,
  TRS postmultiplied `T*R*S`.
- Slicer: RAS (+X = Right, +Y = Anterior, +Z = Superior), millimetres (scene length unit may differ; OpenAnatomy reads it and uses
  `scaleToMeters = 0.001` for `"mm"`).
- Conversion (anatomical "up" = Superior, "forward/toward viewer" = Anterior... glTF front faces +Z so a patient facing the viewer has
  Anterior = +Z; OpenAnatomy instead maps to LSA, i.e. patient's left = +X). **Decision needed** (`[TODO decide in protocol]`): the
  mathematically simplest right-handed mapping is
  `[x, y, z]_gltf = [R, S, -A] * 0.001` — matrix `M = s·[[1,0,0],[0,0,-1],[0,1,0]]` applied to `(R,A,S)`, det = +1, so triangle winding is
  unchanged; equivalently the OpenAnatomy root matrix (column-major) `[s,0,0,0, 0,0,-s,0, 0,s,0,0, 0,0,0,1]` [S35]. With this
  mapping the patient faces **−Z** (away from the default glTF front); viewers can rotate the root node 180° about Y if the patient should
  face the camera. Apply the same `M` to node matrices: `M_gltf = C · M_ras · C⁻¹` with `C = M` above, and to normals (rotation only).
- Alternative: keep the stream in RAS mm and let web/Quest apply the fixed root transform — simpler Python, same result; protocol must then
  state "coordinates: RAS, mm" explicitly.

## 5. Mesh decimation in VTK

| | `vtkQuadricDecimation` [S37] | `vtkDecimatePro` [S38] |
|---|---|---|
| Algorithm | edge collapse, quadric error (Garland–Heckbert) | vertex removal + retriangulation (Schroeder), optional splitting |
| Topology | not explicitly guaranteed; "actual reduction may be less depending on triangulation, topological constraints" | `PreserveTopologyOn()` keeps it but may miss target; target guaranteed only with `PreserveTopologyOff`, `SplittingOn`, `BoundaryVertexDeletionOn`, `MaximumError=VTK_DOUBLE_MAX` |
| Controls | `TargetReduction` (fraction), `MaximumError` (absolute), `AttributeErrorMetric` + `Normals/Scalars/TCoordsAttribute`, `VolumePreservation`, `Regularize` (better element quality, slightly less precision), `MapPointData` | `TargetReduction`, `PreserveTopology`, `Splitting`, `BoundaryVertexDeletion`, `FeatureAngle` (default 15°), `MaximumError`, `AccumulateError` |
| Input | triangles only → `vtkTriangleFilter` first | triangles only → `vtkTriangleFilter` first |
| Normals | not stated → recompute with `vtkPolyDataNormals` (SplittingOff) afterwards (OpenAnatomy does so) [S35] | same |
| Used in Slicer | Surface Toolbox "FastQuadric"/"DecimatePro" via `Decimation` CLI, default reduction 0.8; FastQuadric "provides more even element sizes but cannot be forced to preserve boundary", DecimatePro "can preserve boundary edges but tend[s] to create more ill-shaped triangles" [S40] | segmentation closed-surface conversion: `vtkDecimatePro`, `PreserveTopologyOn`, `SetMaximumError(1)`, only if factor > 0 [S39] |

Typical sizes: a CT organ segmentation produced by flying edges at 0.5–1 mm voxels yields on the order of 10⁵–10⁶ triangles per
segment before decimation; users report exported STL/OBJ around 100 MB (≈2 M triangles at 50 B/triangle in STL) [S46]. Smoothing does not
reduce count; only the decimation factor does ("0.8 means that 80% of the triangles will be removed" — Pinter) [S46]. `[TODO measure]`
on sample data (e.g. `MRHead`/`CTChest` segmentations) in the manual test plan. Proposed export budget: decimate to ≤ 100 k triangles per
node for mobile/Quest (Quest-side budget to be confirmed by `quest` research), with `vtkQuadricDecimation` + `vtkPolyDataNormals`; fall back
to `vtkDecimatePro(PreserveTopologyOn)` when the quadric result is degenerate (zero triangles). Both run on the main thread (VTK) — for
multi-million-triangle inputs this blocks the GUI for seconds; expose a progress dialog and process one node per timer tick.

## 6. Python packages in Slicer

- Slicer is a self-contained virtual Python environment (3.12.10 in 5.12.4) with pip [S2][S30].
- Dependency API (`slicer.packaging`, present in `v5.12.4`, **absent in `v5.10.0`**) [S31][S53]:
  `pip_ensure(requirements, constraints=None, skip_packages=None, prompt_install=True, prompt_restart=True, requester=None,
  skip_in_testing=True, show_progress=True)`, `pip_install(requirements, ..., blocking=True, show_progress=True, ...)`, `pip_check(req)`,
  `load_requirements(path)`, `load_pyproject_dependencies(path)`, `isPipInstallInProgress()`. `slicer.util.pip_install` still exists and
  delegates to `slicer.packaging.pip_install` [S50]. `pip_install` "simply calls `python -m pip install`" as a subprocess, with a modal
  progress dialog in blocking mode [S31].
- FAQ rules [S30]: never install "in the global scope ... or in the module class constructor"; "Ask the user before installing"; document
  dependencies in `requirements.txt`; use `>=X.Y` not pinned versions; prefer packages distributed as wheels; `pip_ensure` "automatically
  skips installation when running in testing mode".
- Pattern: `Resources/requirements.txt` → in `Logic.ensureDependencies()`:
  `slicer.packaging.pip_ensure(slicer.packaging.load_requirements(self.resourcePath("requirements.txt")), requester="SlicerRemoteView")`,
  called from the "Start session" button, with the import done lazily afterwards.
- WebSocket candidates:
  - `websockets` (latest 17.2, 2026-10-03): threading-based `websockets.sync.client.connect(uri, ssl=..., additional_headers=...,
    open_timeout=10, ping_interval=20, ping_timeout=20, close_timeout=10, max_size=1048576, ...)`; `ClientConnection.recv(timeout=None)`,
    `send(bytes|str)` (bytes → Binary frame), `ping()`, `close()`; `reconnect()` with exponential backoff; `recv()` from two threads raises
    `ConcurrencyError`. Sync implementation since 11.0; 14.x/15.x need Python ≥ 3.9, 16.x ≥ 3.10, 17.x ≥ 3.11 — all fine on 3.12.
    `max_size` must be raised for large inbound frames only if the relay ever pushes binary to Slicer (it should not). Thread-safety of
    concurrent `send` (thread A) and `recv` (thread B) is not documented → use a single IO thread with `recv(timeout=0.05)` polling and
    draining the outbound queue, or two threads with a lock around `send` `[TODO verify]`. [S28][S29]
  - `websocket-client`: `WebSocketApp(url, on_open, on_message, on_close, ...)`; `Thread(target=ws.run_forever).start()`;
    set `enable_multithread=True` when used from several threads [S54]. Callback-style; fine as fallback.
  - asyncio-based clients (`aiohttp`, `websockets.asyncio`) are **not** recommended inside Slicer (no loop integration, §3).
- TLS: Slicer ships `Slicer.crt` (Mozilla bundle, regenerated weekly) and sets `SSL_CERT_FILE`; Python's `ssl.create_default_context()`
  loads it/system stores; corporate SSL-bumping proxies break verification and users work around it with `REQUESTS_CA_BUNDLE`/system CA
  [S55]. Our client must pass an explicit `ssl.create_default_context()` and surface certificate errors in the UI; never offer
  "disable verification" `[TODO verify SSL_CERT_FILE handling in 5.12.4 launcher settings]`.

## 7. QR code in the module panel

- `segno` (1.6.6, 2025-03-12): "Pure Python QR Code generator with no dependencies"; `segno.make(content, error=None, version=None, ...)`;
  `qr.save(out, kind="png", scale=10, border=4, dark="black", light="white")` writes PNG (grayscale/palette) without Pillow; also
  `kind="svg"`, `svg_data_uri()`, `png_data_uri()`, `matrix` (tuple of bytearray), `matrix_iter(scale, border)` [S41].
- `qrcode` (8.2, 2025-05-01, Python ≥ 3.9): PNG via `qrcode.image.pure.PyPNGImage` (needs `pypng`) or Pillow (`qrcode[pil]`); SVG via
  `qrcode.image.svg.SvgPathImage` [S42].
- Rendering in PythonQt: `QPixmap.loadFromData(const QByteArray&, ...)` — PythonQt converts Python `bytes` to `QByteArray` for by-value
  parameters (`PyObjGetBytes` → `QByteArray(PyBytes_AS_STRING, PyBytes_GET_SIZE)`); return values stay wrapped `QByteArray` objects
  (`.data()` to read) [S43]. Code sketch:
  `buf = io.BytesIO(); segno.make(url).save(buf, kind="png", scale=8, border=2); pix = qt.QPixmap(); pix.loadFromData(buf.getvalue()); label.setPixmap(pix)`
  `[TODO verify in Slicer 5.12 that const-ref QByteArray parameters take bytes; fallback: write to tempfile and qt.QPixmap(path)]`.
- Zero-dependency fallback: build a `qt.QImage(w, h, qt.QImage.Format_RGB32)` and `setPixel` from `qr.matrix_iter(scale=1)` — no PNG
  decoding needed, ~20 lines, avoids the bytes→QByteArray question entirely.
- UI: `qt.QLabel` with `setScaledContents(False)`, pixmap regenerated at a fixed size (≥ 240×240 px, border ≥ 2 modules); show the 5-char code
  as large text (`font-size: 28pt`, monospace) next to it, and a "Copy link" button. The QR payload should be the viewer URL with the code as
  a fragment (`https://<web>/#<CODE>`), not a path or query (CLAUDE.md rule 6: codes must not land in URL paths/logs) `[protocol decision]`.
- Readability: version-1/2 QR with high error correction (segno picks maximal EC for the content by default) is readable from a phone at
  arm's length when modules are ≥ 6–8 screen px; keep the URL short (≤ 40 chars).

## 8. Known limits and startup behaviour

- Startup: module Python files are imported at application start; heavy imports or pip installs there slow every launch (SlicerHeart case:
  ~18 s first start due to pandas install) and can fail on bad networks; policy is install on first use [S30][S45]. Kitware measured 25 %
  startup gain just by delaying the SimpleITK import [S45]. Keep `SlicerRemoteView.py` import-light (`json`, `struct`, `numpy`, `qt`,
  `vtk`, `slicer` only); import `websockets`/`segno` inside functions.
- Memory: Slicer recommends >4 GB (8+) and about 10× the data size; mesh copies for export (DeepCopy + numpy float32 + GLB bytes) roughly
  triple the per-node footprint transiently — process nodes sequentially and release references [S44].
- Large scenes: closed-surface creation for whole-body segmentations takes seconds to minutes and happens on the main thread; the exporter
  must not call `CreateClosedSurfaceRepresentation()` silently on huge segmentations without a progress dialog; consider exporting only
  segments visible in 3D (`GetVisibleSegmentIDs()`).
- Scene close/reload: all node IDs change (new scene) → the session must send a `scene.reset` message on `EndCloseEvent`/`EndImportEvent`.
- Qt 5 vs Qt 6 builds of 5.12: PythonQt API is the same for our use (`qt.QTimer`, `qt.QLabel`, `qt.QPixmap`); avoid Qt5-only enums.
- Testing without Slicer (CLAUDE.md rule 10): keep GLB writer, debounce logic, coordinate conversion and protocol encoding in pure modules
  with numpy-only inputs; Slicer-specific adapters in one file; `ScriptedLoadableModuleTest` exercises them on sample data
  (`SampleData` + `slicer.modules.segmentations.logic()`) as the manual/CTest path.
