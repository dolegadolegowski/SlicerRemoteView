# Env parity check: variables the relay does not parse

- **Reported by**: server (`ws/server`, commit `00409d4`, SRV-02)
- **Affects**: deploy — DEP-05 env parity check between `docs/architecture.md` §9, `.railway/railway.ts` and
  `relay-server/README.md`
- **Severity**: low
- **Milestone**: M1
- **Protocol**: — (configuration only)
- **Status**: open

## Steps to reproduce

1. Compare the variable names of `docs/architecture.md` §9 with `relay-server/.env.example` and the
   `ENV_VARIABLES` list in `relay-server/src/config.ts`.

## Expected

The parity check knows which names are not parsed by `config.ts` and therefore never appear in
`relay-server/.env.example` (SRV-02 criterion 3 keeps that file equal to what `loadConfig` reads):

- `NODE_OPTIONS` — set by `relay-server/Dockerfile` (SRV-20), read by Node itself;
- `RAILWAY_PUBLIC_DOMAIN` — injected by Railway, used only as the default of `ALLOWED_ORIGINS`;
- `RELAY_TEST_FAST_TIMERS` — test-only (already excluded per the plan).

## Actual

The plan mentions only `RELAY_TEST_FAST_TIMERS` as an exclusion.

## Notes / suspected cause

`relay-server/README.md` lists `NODE_OPTIONS` and `RAILWAY_PUBLIC_DOMAIN` in prose under "Configuration", not in
the variable table, so a parity script that reads the table sees exactly the `config.ts` variables.
