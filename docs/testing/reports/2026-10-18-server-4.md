# Session state diagram and ADR 0008 §3: grace before the first snapshot, idle timer refresh

- **Reported by**: server (`ws/server`, commit `65145a3`, SRV-04 review)
- **Affects**: release — `docs/architecture.md` §3 (state diagram), ADR 0008 §3 (lifecycle wording)
- **Severity**: low
- **Milestone**: M1
- **Protocol**: v1.0 §4.3 (resume allowed while the session is in grace), §4.4 (idle timer), §4.6
- **Status**: open

## Steps to reproduce

1. Compare the state diagram of architecture §3 with `relay-server/src/registry.ts` (SRV-04).
2. Compare ADR 0008 §3 ("publisher heartbeat every 15 s refreshes" the session TTL) with protocol §4.4.

## Expected

Diagram, ADR and protocol describe the same lifecycle.

## Actual

- The relay also moves `allocated → grace` when the publisher drops **before** its first snapshot, and
  `grace → allocated` when it resumes without one. Without these edges such a publisher could not resume, and its
  fallback `session.create{preferredCode}` would get a fresh code (the old one is still live), so the code on the
  lecture screen would stop working. `tools/fake-slicer` (PRO-16) already relies on resuming in this state. The
  diagram only has `active → grace` and `grace → active`.
- ADR 0008 §3 says publisher heartbeats refresh the session TTL. Protocol §4.4 (normative) and the relay say the
  idle timer runs only while no viewer is connected and is reset only by viewers leaving/joining and by
  `session.renew`; publisher activity does not refresh it.

## Notes / suspected cause

Please add the two edges to the architecture §3 diagram and an erratum to ADR 0008 §3. No protocol change.
