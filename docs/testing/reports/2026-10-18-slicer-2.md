# `jsonschema` as a Slicer runtime dependency contradicts FR-16 / T12

- **Reported by**: slicer (`ws/slicer`, SLC-02/SLC-03 review)
- **Affects**: protocol — `shared/py/README.md` ("the slicer workstream installs `jsonschema`"); release —
  `docs/requirements.md` FR-16, `docs/architecture.md` §8 T12
- **Severity**: low
- **Milestone**: M1
- **Protocol**: v1.0 (packaging of `shared/py`, ADR 0007 §3)
- **Status**: open

## Steps to reproduce

1. Read `shared/py/README.md` § "How it is consumed": the vendored copy needs `jsonschema` and the slicer workstream
   is told to `pip_install` it in Slicer.
2. Read FR-16 and T12: Slicer runtime dependencies are limited to `websockets` and `segno`, installed after consent;
   the module's consent text says the same.

## Expected

One rule. Installing `jsonschema` would also pull `referencing`, `attrs`, `jsonschema-specifications` and the native
`rpds-py` into the presenter's Slicer.

## Actual

`remoteview_protocol/__init__.py` imports `schemas` → `jsonschema` unconditionally, so even the stdlib-only helpers
(`chunk_header`, `alphabet`) cannot be imported through the package without it.

## Notes / suspected cause

Decision in the slicer workstream (`docs/plan/slicer.md` Follow-ups): `jsonschema` stays **test-only**;
`remoteview_core.vendored` registers the package without its `__init__` when `jsonschema` is missing and uses only
`chunk_header`/`alphabet`; schema validation runs in pytest. Options for `protocol`/`release`: make the
`schemas`/`envelope` imports in `remoteview_protocol/__init__.py` lazy (or optional), and/or update FR-16, T12 and the
consent text if runtime validation in Slicer is wanted. Also low: `shared/py` does not select ruff's bandit rules
(`S`) although the code ships into Slicer (the slicer config excludes `_vendor/`).
