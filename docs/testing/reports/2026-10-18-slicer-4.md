# Sheared linear transforms cannot be a glTF `node.matrix`

- **Reported by**: slicer (`ws/slicer`, SLC-05 review, commit `d0e5540`)
- **Affects**: protocol — `docs/protocol.md` §7.2 (`T.matrix`), §8.1 (`scene.update.matrix`); web, quest (viewers);
  slicer — SLC-13/SLC-16
- **Severity**: medium (wrong pose shown without any error — same class as a wrong orientation)
- **Milestone**: M2
- **Protocol**: v1.0 §7.2, §8.1
- **Status**: triaged (PRO-20: TRS-only, wider `baked`; release docs: 2026-10-27-protocol-4)

## Steps to reproduce

1. In Slicer, put a model under a linear transform with shear (common after affine registration).
2. Export it with the transform in `T.matrix` = `C·M_world·C⁻¹` (protocol §7.2 / ADR 0005 errata).

## Expected

Viewers show the same geometry as Slicer.

## Actual (expected behaviour of the viewers, `[TODO verify]` in three.js `GLTFLoader` and glTFast)

glTF 2.0 requires `node.matrix` to be decomposable into translation, rotation and scale (gltf-validator
`NODE_MATRIX_NON_TRS`); three.js decomposes node matrices into position/quaternion/scale and Unity transforms are TRS,
so the shear is silently dropped and the model appears in a different shape/pose.

## Notes / suspected cause

Proposed protocol note for §7.2/§8.1: "`T.matrix` and `scene.update.matrix` MUST be TRS-decomposable (affine, no
shear); otherwise the publisher bakes the transform into the vertices (`baked: true`, identity `T.matrix`) and re-exports
on change, as for non-linear transforms." The slicer workstream added `remoteview_core.coords.is_trs_decomposable` (SLC-05)
and will treat sheared world matrices like non-linear ones in SLC-13/SLC-16 (plan Follow-ups).

**Update (SLC-13, 2026-10-21):** from SLC-13 on the publisher bakes every world matrix the writer's
`is_exportable_matrix` refuses — shear, a zero scale, a scale that overflows float32 — and sends `baked: true` with an
identity `T.matrix`, like a non-linear transform. Protocol §7.3 ("a non-linear transform was applied"), the ADR 0005
errata and architecture §6.4 still describe the non-linear case only: please align them with the note above.
