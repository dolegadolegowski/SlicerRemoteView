# Code release on `session.close` vs the quarantine; a value entry point for `parseEnvelope`

- **Reported by**: server (`ws/server`, branch audit after SRV-06, commit `52fe109`)
- **Affects**: protocol — `docs/protocol.md` §3.1, §4.1 and §4.5; `shared/ts/validate.ts` (`parseEnvelope`)
- **Severity**: low
- **Milestone**: M1
- **Protocol**: v1.0 §3.1, §3.2, §4.1, §4.5
- **Status**: triaged (PRO-20 for §3.1/§4.1/§4.5; `parseEnvelopeValue` in PRO-24)

## Steps to reproduce

1. Publisher A: `session.create` → `session.created{code: C}`, then `session.close`.
2. Within `CODE_QUARANTINE_S` (600 s), publisher B: `session.create{preferredCode: C}`.

## Expected

§4.5 says "The relay frees the code immediately", and §4.1 grants `preferredCode` "only if the code is currently
free". Read literally, B gets C.

## Actual

B gets a fresh code. The relay keeps every released code in a quarantine for `CODE_QUARANTINE_S` and treats it as
taken, as ADR 0008 (decision and errata: "free = neither in `byCode` nor in the quarantine set") and architecture §3
require. This is intended: a viewer typing a recently ended code must not land in someone else's session (T1, T5).
Only the contract's wording disagrees.

## Notes / suspected cause

Suggested wording:

- §4.5: "The relay releases the code into the `CODE_QUARANTINE_S` quarantine (ADR 0008), drops the snapshot buffer, …".
- §4.1: "Granted only if the code is currently free, that is, neither live nor quarantined".

## Related: `parseEnvelope` takes only text

The relay parses each text frame once. It needs the frame's `type` before the role is known (§3.3 size limit), and the
`type` and `id` again when validation fails (role gate, `replyTo`). A 256 KiB frame of dense JSON costs about 10–20 ms
per `JSON.parse`, so parsing it three times was a pre-handshake CPU amplification (branch audit, medium). Because
`parseEnvelope(text)` parses internally, `relay-server/src/ws/frame.ts` (`checkEnvelope`) repeats its checks 2–5
on the parsed value. A relay test compares the two over every fixture in `shared/fixtures/messages` to catch drift.

Suggestion for the protocol workstream: export a value entry point from `shared/` (e.g. `parseEnvelopeValue(value)`,
which `parseEnvelope` calls after `JSON.parse`) so that receivers can parse once without copying the checks. The relay
would then drop its copy.

## Related: subprotocols on `/ws` (§3.1)

§3.1 forbids codes, tokens and roles in `Sec-WebSocket-Protocol`. The relay goes one step further: it selects no
subprotocol and refuses every upgrade that offers one with HTTP 400 (commit `e82a444`), because `ws` would
otherwise echo the client's first offer in the `101` response. No client in the repo offers one today. So that client
workstreams learn this from the contract, suggested sentence for §3.1: "Clients offer no subprotocol; the relay
refuses upgrades that carry `Sec-WebSocket-Protocol` with HTTP 400."
