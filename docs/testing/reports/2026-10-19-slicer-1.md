# Future `slicer-plugin` CI must run the Khronos glTF validator tests, not skip them

- **Reported by**: slicer (`ws/slicer`, SLC-04 review, commit `c8bac27`)
- **Affects**: deploy — the GitHub Actions job that will run `slicer-plugin` tests (none exists yet in `.github/`)
- **Severity**: low (no defect today; prevents a silently disabled spec gate later)
- **Milestone**: M1
- **Protocol**: v1.0 §7.1 (GLB validity rules)
- **Status**: open

## Steps to reproduce

1. Run `slicer-plugin/.venv/bin/pytest slicer-plugin -k glb_writer -rs` in an environment without `npm ci`
   (no `node_modules/gltf-validator` at the repository root) or without Node 22.

## Expected

In CI the GLB snapshots written by `remoteview_core/glb_writer.py` are always checked by the Khronos glTF validator
(0 errors, 0 warnings) and the §7.1 pre-checks of `slicer-plugin/tests/validate_glb.mjs`.

## Actual

The validator tests are skipped (listed by `pytest -rs`) so a developer machine without Node still passes. They fail
instead of skipping only when `REMOTEVIEW_REQUIRE_GLTF_VALIDATOR=1` is set.

## Notes / suspected cause

Request for the `deploy` workstream: in the job that runs the `slicer-plugin` tests, run `npm ci` at the repository
root (Node 22), create the venv from `slicer-plugin/requirements-dev.txt` (Python 3.12) and set
`REMOTEVIEW_REQUIRE_GLTF_VALIDATOR=1` for `pytest slicer-plugin -W error`. Commands: `slicer-plugin/README.md`
(Development).
