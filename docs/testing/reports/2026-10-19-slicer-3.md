# Segment IDs outside the §3.3 `nodeId` character set have no defined mapping

- **Reported by**: slicer (`ws/slicer` branch audit, commit `db3a42b`)
- **Affects**: protocol — `docs/protocol.md` §3.3 (`nodeId` grammar), §7.3 (`nodeId` of a segment); slicer —
  SLC-07/SLC-13 (`remoteview_core/glb_writer.py`)
- **Severity**: medium (one such segment makes the whole snapshot fail; the obvious workaround is not allowed today)
- **Milestone**: M2
- **Protocol**: v1.0 §3.3, §7.3
- **Status**: in progress (SLC-27: alias registry and writer rules; the segment export itself SLC-35–SLC-37)

## Steps to reproduce

1. In Slicer 5.12.4 create a segment with an explicit ID, e.g. from the Python console
   `segmentation.AddEmptySegment("left lung", "Left lung")`, or load an older scene / a scene written by another tool
   whose segment IDs contain spaces, non-ASCII letters, parentheses or more than ~100 characters. Slicer keeps a
   caller-supplied ID unchanged (`Libs/vtkSegmentationCore/vtkSegmentation.cxx`: `GenerateUniqueSegmentID` returns it
   as is, `AddEmptySegment` passes it through); only IDs Slicer generates itself are safe (`S_` + 16 alphanumerics).
2. Export the scene: §7.3 makes the segment's `nodeId` `"<segmentationNodeID>/<segmentID>"` verbatim.

## Expected

Every segment Slicer accepts can be exported; the GLB and `scene.update` stay within §3.3
(`[A-Za-z0-9_./:-]{1,128}`).

## Actual

`"vtkMRMLSegmentationNode1/left lung"`, `".../Läsion"`, `".../Tumor(1)"` and a 110-character ID violate §3.3, so the
writer (correctly, per the contract) raises `GlbWriteError` and no snapshot is sent at all. Using a stable alias as
`nodeId` and keeping the raw ID only in `extras.segmentId` is not possible either: §7.3 defines `nodeId` as exactly
`<segmentationNodeID>/<segmentID>`.

## Notes / suspected cause

Proposal for §7.3: "If `<segmentID>` is not within the §3.3 character set, or the resulting `nodeId` exceeds 128
characters, the publisher uses a stable per-session alias `<segmentationNodeID>/s_<n>` as `nodeId`; `extras.segmentId`
carries the raw ID (or is omitted when names are hidden)." The same alias also solves report `2026-10-18-slicer-3`
(segment IDs derived from names under *Hide node names*): in anonymised mode the publisher would always use the alias.
Until `protocol` decides, the slicer workstream skips such segments in SLC-07/SLC-13 and reports them as skipped
(plan Follow-ups).
