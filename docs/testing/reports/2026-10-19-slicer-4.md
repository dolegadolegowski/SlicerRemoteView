# Must `scene.snapshot.begin` match the GLB's root extras?

- **Reported by**: slicer (`ws/slicer` branch audit, commit `db3a42b`)
- **Affects**: protocol — `docs/protocol.md` §6.2 (`scene.snapshot.begin`), §7.1 (root `extras`), shared fixtures in
  `shared/fixtures/glb` + `shared/fixtures/messages/scene.snapshot.begin`; web, quest (which value they trust)
- **Severity**: low
- **Milestone**: M1
- **Protocol**: v1.0 §6.2, §7.1
- **Status**: triaged (SLC-38: `begin_snapshot` checks the root extras and the totals against the `begin`)

## Steps to reproduce

1. Compare `shared/fixtures/glb/large-synthetic.glb` (root `extras.sceneVersion` 1) with
   `shared/fixtures/messages/scene.snapshot.begin/valid-large-synthetic.json` (`sceneVersion` 3), and
   `quantized-1node.glb` (root 1) with `valid-quantized-1node.json` (`sceneVersion` 2).
2. Read §6.2 and §7.1: both carry `sceneVersion` and `profile`; `begin` also carries `nodeCount`/`triangleCount`.

## Expected

The contract says whether `begin.sceneVersion`/`profile` MUST equal the GLB's root `extras.sceneVersion`/`profile`
(and whether `nodeCount`/`triangleCount` must equal the GLB's entity and triangle totals), and which one a viewer
trusts when they differ.

## Actual

Nothing is stated and the shared fixtures disagree with each other, so the publisher can announce one version while
the file says another. The slicer client (`remoteview_core/protocol_client.py`, SLC-06) does not compare them today.

## Notes / suspected cause

Proposal: "`begin.sceneVersion` and `begin.profile` MUST equal the GLB root `extras.sceneVersion`/`profile`;
`nodeCount` is the number of `T` nodes and `triangleCount` the sum of their `triangleCount`." Then regenerate the two
fixtures. The slicer workstream will check this in `ProtocolClient.begin_snapshot` (plan Follow-ups).
