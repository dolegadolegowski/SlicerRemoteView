# §7.3 "name ≤ 64 chars" does not say what a character is

- **Reported by**: slicer (`ws/slicer`, SLC-23 review, on top of `0731292`)
- **Affects**: protocol — `docs/protocol.md` §3.3 (limits table: "Node `name` length … ≤ 64 chars"), §7.3;
  `shared/ts/constants.ts` `MAX_NODE_NAME_LENGTH` ("chars"); web, quest (any viewer that validates or truncates names)
- **Severity**: low (no interoperability failure today; a viewer and the publisher can disagree on the limit)
- **Milestone**: M1
- **Protocol**: v1.0 §3.3, §7.3
- **Status**: open

## Steps to reproduce

1. Take a name of 64 astral characters, e.g. 64 × U+1F600.
2. Count it in Python (`len(name) == 64`, code points) and in JavaScript (`name.length === 128`, UTF-16 code units);
   C# `string.Length` also counts UTF-16 units.

## Expected

One definition of the 64-character limit, so a name the publisher sends is never "too long" for a viewer.

## Actual

The contract says "chars". The slicer publisher (`remoteview_core/names.py`, SLC-23) cuts names to **64 UTF-16 code
units**, which satisfies both readings (≤ 64 code points as well); the GLB writer checks ≤ 64 code points.

## Notes / suspected cause

Proposed wording for §3.3/§7.3: "≤ 64 UTF-16 code units after sanitisation (the length JavaScript and C# report)",
and the same in `shared/ts/constants.ts`.
