# Notes from serving the viewer (SRV-16): CSP pointer, `/j?query`, HSTS

- **Reported by**: server (`ws/server`, SRV-16 review)
- **Affects**: protocol/release — `docs/protocol.md` §10, `docs/architecture.md`; qa — QA-05 negative tests;
  deploy — custom-domain notes in `docs/deploy.md`
- **Severity**: low
- **Milestone**: M1
- **Protocol**: v1.0 §10
- **Status**: open

## Steps to reproduce

1. `GET /j` on a relay with SRV-16 and read the response headers.
2. `GET /j?code=7KQ4X`.

## Expected

§10: security headers are "a relay implementation detail recorded in `docs/architecture.md`", with
`worker-src blob:`; ADR 0006's QA follow-up: "`GET /j?code=X` and `GET /ABCDE` must not serve the viewer with the
code".

## Actual

- The CSP follows ADR 0006 §4 (`worker-src 'self' blob:`, the accepted decision); `docs/architecture.md` records
  no CSP (T6 mentions only `Referrer-Policy`). The exact header is in `relay-server/README.md` ("HTTP endpoints").
- `/j?code=7KQ4X` answers `200` with the same bytes as `/j`; nothing of the query is echoed (body or headers) or
  logged, and the viewer reads only the fragment and replaces the URL with `/j` (WEB-11). A `404` would not keep the
  query out of the edge log (the request has been made by then) and would break links that messengers decorate
  with `?fbclid=…`. `/ABCDE`, `/j/ABCDE` and `/join?code=X` are `404`.
- HSTS is `max-age=31536000; includeSubDomains` (helmet's default). On `*.up.railway.app` it covers only the
  relay's own host and its subdomains (RFC 6797 §6.1.2).

## Notes / suggested change

- Release: point §10 at ADR 0006 §4 (or record the CSP in `docs/architecture.md`) and align `worker-src` with it.
- QA (QA-05): write the `/j?code=X` negative test as "`200`, body identical to `/j`, no echo", not as a `404`.
- Deploy: on a custom domain, `includeSubDomains` forces HTTPS for a year on every subdomain of the relay's host;
  serve the relay on a dedicated host name (e.g. `view.example.org`), not an apex domain, and say so in
  `docs/deploy.md`.
