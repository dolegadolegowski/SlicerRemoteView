# Relay log lines for the first-deploy checklist (DEP-06)

- **Reported by**: server (`ws/server`, SRV-18)
- **Affects**: deploy — DEP-06 (`docs/plan/deploy.md`) and its checklist, `docs/deploy.md` §4 "First deploy checklist"
- **Severity**: low
- **Milestone**: M1
- **Protocol**: none (operations)
- **Status**: open

## Steps to reproduce

1. Start the relay image (`node dist/index.js`) and read its first log lines.
2. Connect one WebSocket client (e.g. `fake-slicer`) and read the next line.

## Expected

DEP-06: "`X-Forwarded-For` presence confirmed from the relay's startup/first-upgrade log line, which records only
`xff: present|absent` and the HMAC'd key"; "read `heapSizeLimit` from the relay's single startup `info` log line".

## Actual

- `relay starting` — `{heapSizeLimit, maxTotalBufferedBytes, maxTotalSnapshotBytes, trustProxy}`, before the port is
  bound; then one `http server listening` per network interface (no address) and `relay listening` with the port.
- `first websocket upgrade` — once per start, for the first upgrade that passes the Origin and subprotocol checks:
  `{xff: "present" | "absent", xffEntries, clientKey}`. `xffEntries` (only with `present`) counts the comma-separated
  entries of `X-Forwarded-For`, the client's own included; `clientKey` is the HMAC of the client address with a
  per-start key (`relay-server/src/ratelimit.ts`), never the address.

## Notes / suggested change

- Name the two lines in `docs/deploy.md` §4 and drop "single startup line".
- Read `xffEntries` from a client that sends no `X-Forwarded-For` of its own (fake-slicer on a direct connection,
  not behind a corporate or hospital proxy), as the first upgrade after a deploy: `1` means the edge is the only hop
  (`TRUST_PROXY=true` is right as is); more means extra internal hops (report
  `docs/testing/reports/2026-10-18-server-1.md`). A count read through a client-side proxy would overstate the hops,
  and trusting more hops than there are lets clients forge their address (T1, T3).
