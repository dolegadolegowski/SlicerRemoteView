# Relay image: `.dockerignore` gaps, heap share vs off-heap budgets, smoke test in CI

- **Reported by**: server (`ws/server`, SRV-20 review)
- **Affects**: release — root `.dockerignore`, `docs/architecture.md` §4 (memory budget), ADR 0007 §5; deploy — DEP-03
  (image build in CI), DEP-06/DEP-08 (service memory)
- **Severity**: medium
- **Milestone**: M1
- **Protocol**: none (operations)
- **Status**: open

## Steps to reproduce

1. Put `relay-server/.env` (as `relay-server/README.md` suggests for local runs) next to the sources and run
   `docker build -f relay-server/Dockerfile .`.
2. Run the image with `--memory 1g` and the default budgets under full load (512 MiB of cached snapshots, 160 MiB of
   send buffers).
3. Build the image in CI and run only the planned `/healthz`/`/api/version`/uid checks.

## Expected

1. No local secret reaches the build (CLAUDE.md rule 6).
2. Architecture §4: snapshots + send buffers + a heap under 200 MiB fit in a 1 GiB container.
3. The CI image is checked for what the relay relies on (dumb-init as PID 1, production dependencies only).

## Actual

1. Low: `.env` and `.env.*` in the root `.dockerignore` match at the context root only: `relay-server/.env`,
   `web-viewer/.env.production.local`, nested `.npmrc` files and key files reach `COPY . .` in the build stage. They
   are not in the shipped image (its stage copies only manifests and build outputs), but they stay in the build cache
   and in any `--target build` image or exported cache.
2. Medium: ADR 0007 §5 sets `NODE_OPTIONS=--max-old-space-size-percentage=75`: in 1 GiB the heap may grow to 768 MiB, on top
   of up to 672 MiB of off-heap `Buffer`s (measured: the limit follows `--memory`, ≈ 195 MiB at 256 MiB).
3. Low: `relay-server/test/docker-smoke.test.ts` checks more (PID 1, `CMD`, non-writable app, clean SIGTERM, heap sizing,
   no dev dependency, docs or symbolic links) but runs only when `RELAY_IMAGE` names an image. In the sandbox the
   Alpine CDN is blocked, so `apk add dumb-init` and the Docker Hub base were never exercised.

## Notes / suggested change

- Release (`.dockerignore`): add `**/.env`, `**/.env.*`, `!**/.env.example`, `**/.npmrc`, `**/*.pem`, `**/*.key`.
- Release (architecture §4 / ADR 0007): pick one — a lower heap share (≈ 25–30 %), a container of ≥ 1.5 GiB, or lower
  default budgets — and record the arithmetic. The relay could also warn at start when `heapSizeLimit` plus both
  budgets exceed `process.constrainedMemory()` (a server task once decided).
- Deploy (DEP-03): after building the image, run
  `RELAY_IMAGE=<that tag> npm test -w relay-server -- docker-smoke` (it needs Docker on the runner); it is the only
  check that PID 1 is the real `/usr/bin/dumb-init`.
- Release: ADR 0006 asks deploy to generate `.br`/`.gz` variants of the viewer "in the Docker build", but the
  Dockerfile is server's (`relay-server/`): assign that step to server (a `todo` in `docs/plan/server.md`) or confirm it
  stays with deploy. `@fastify/static` already prefers the variants when present (SRV-16).
