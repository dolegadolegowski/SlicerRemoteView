# Threat model T5 omits TLS-inspecting proxies and Slicer's end-of-life OpenSSL

- **Reported by**: slicer (`ws/slicer`, SLC-08, on top of `99d1121`)
- **Affects**: release — `docs/architecture.md` §8 (threat model, row T5); architect — `docs/research/slicer.md`
  (the paragraph on `ssl.create_default_context()` trust and open question 5)
- **Severity**: medium (a documented control is weaker than the threat model says on hospital networks)
- **Milestone**: M1
- **Protocol**: v1.0 §3.1 (WSS only)
- **Status**: triaged (D5: no protocol text; release, 2026-10-27-protocol-4)

## Steps to reproduce

1. On Windows, install a corporate root CA into the Windows certificate store (what Group Policy does for TLS
   inspection: Zscaler, Palo Alto, Fortinet, …) and route Slicer through the inspecting proxy.
2. Start a RemoteView session (SLC-08 transport, `ssl.create_default_context()`).
3. Repeat on macOS or Linux with the same proxy.

## Expected

T5 lists every party that can read the WebSocket: Railway's edge, and — where the institution inspects TLS — its
proxy, so the institution's DPO can decide whether that is acceptable for PHI.

## Actual

- Windows: CPython loads the Windows "CA"/"ROOT" stores (including Group Policy CAs) before `SSL_CERT_FILE`
  (`Slicer.crt`), so the inspecting proxy's certificate verifies and the proxy can read the scene, the session code and
  the `publisherToken`. Verification is on and working as designed; T5 does not mention this reader.
- macOS/Linux: only `Slicer.crt` is trusted, so the same network fails with certificate code 20; the user needs the
  "additional trusted CA" setting (SLC-08 `extra_ca_file`, UI in SLC-09) and IT's root certificate.
- Slicer 5.12.4 builds CPython against OpenSSL 1.1.1w (Linux/macOS) and a pre-built 1.1.1g (Windows), both end of
  life (1.1.1g lacks e.g. the CVE-2022-0778 fix, an infinite loop reachable from a crafted server certificate). The
  extension cannot change this.
- `docs/research/slicer.md` says `create_default_context()` loads "it/system stores"; true on Windows only — on
  macOS/Linux it loads `Slicer.crt` only (verified facts and links: `docs/research/slicer-transport.md` §2).

## Notes / suspected cause

Proposed additions to T5 "Residual risk": "an institution's TLS-inspecting proxy whose root CA is in the Windows store
can read the session (the UI and the user guide recommend exempting the relay host); Slicer's bundled OpenSSL 1.1.1 is
end of life — connect only to the configured relay host (the transport refuses redirects)". Proposed fix to
`docs/research/slicer.md`: per-OS trust as in `slicer-transport.md` §2.
