# Future `slicer-plugin` CI must run the transport's TLS tests, not skip them

- **Reported by**: slicer (`ws/slicer`, SLC-08 review, on top of `09bcff6`)
- **Affects**: deploy — the GitHub Actions job that will run `slicer-plugin` tests (none exists yet in `.github/`)
- **Severity**: low (no defect today; prevents a silently disabled security gate later)
- **Milestone**: M1
- **Protocol**: v1.0 §3.1 (WSS only); threat model T5
- **Status**: open

## Steps to reproduce

1. Run `slicer-plugin/.venv/bin/pytest slicer-plugin -k transport -rs` on a machine without the `openssl` CLI.

## Expected

In CI the TLS tests of `slicer-plugin/tests/test_transport.py` always run: a self-signed relay certificate is refused
with a `TlsError` and guidance, a certificate for another host is refused, an added CA file is trusted, TLS 1.3
connects do not stall, no TLS key log is written (SLC-08 acceptance criterion 3, ADR 0009).

## Actual

The tests make their certificates with the `openssl` CLI (the dev venv has no `cryptography`) and are skipped without
it. They fail instead of skipping only when `REMOTEVIEW_REQUIRE_OPENSSL=1` is set.

## Notes / suspected cause

Request for the `deploy` workstream: in the job that runs the `slicer-plugin` tests (see
`2026-10-19-slicer-1.md`), make sure `openssl` is on `PATH` (it is on GitHub's Ubuntu runners) and set
`REMOTEVIEW_REQUIRE_OPENSSL=1` next to `REMOTEVIEW_REQUIRE_GLTF_VALIDATOR=1`. Commands: `slicer-plugin/README.md`
(Development).
