# Architecture §6 and the ADR index do not reflect ADR 0009 (Slicer transport on the asyncio client)

- **Reported by**: slicer (`ws/slicer`, SLC-08 review, on top of `c937551`)
- **Affects**: release — `docs/architecture.md` §6 step 6 ("Send (IO thread)"); `docs/adr/README.md` (index)
- **Severity**: low (documentation drift; the code and ADR 0009 agree)
- **Milestone**: M1
- **Protocol**: v1.0 §3.1, §9.1 (unchanged)
- **Status**: open

## Steps to reproduce

1. Read `docs/architecture.md` §6 step 6: "`websockets.sync.client` in a `threading.Thread`; outbound `queue.Queue` …;
   SHA-256 computed on the IO thread".
2. Read `docs/adr/0009-slicer-transport-asyncio-worker-thread.md` and `slicer-plugin/RemoteView/remoteview_core/transport.py`.
3. Look for ADR 0009 in the index of `docs/adr/README.md`.

## Expected

§6 step 6 describes the transport the publisher uses, and the ADR index lists every ADR.

## Actual

- SLC-08 runs the `websockets` **asyncio** client on a private event loop in one daemon worker thread (ADR 0009:
  the sync client stalls on about 10–15 % of TLS 1.3 connects, and its `send()` can block for ever). The application
  heartbeat (§9.1) lives in that thread; frames are queued per connection.
- The SHA-256 of a snapshot stays on the main thread for now (decided in SLC-08, `docs/plan/slicer.md` follow-ups:
  ≈ 0.1 s for the 32 MiB mobile budget), while §6 step 6 puts it on the IO thread.
- ADR 0009 is not in the index (`release` keeps the index current, `docs/adr/README.md`).

## Notes / suspected cause

Proposed §6 step 6: "Send (IO thread): the `websockets` asyncio client on a private event loop in one daemon worker
thread (ADR 0009); frames queued per connection; application `ping`/`pong` in that thread; GLB sliced into 1 MiB
chunks with the `SRVC` header on the main thread (SHA-256 there too, revisited with per-node collection in SLC-14/22);
inbound messages go to a `queue.Queue` drained by a main-thread `qt.QTimer` (50 ms) that also yields
(`time.sleep(0.001)`) so the worker gets the GIL. Reconnect with backoff; on reconnect `session.resume` (SLC-17)."
