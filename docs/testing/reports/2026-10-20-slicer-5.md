# Hidden models: FR-05 ("visible model nodes") and ADR 0005 Decision 6 ("exported with visible: false") disagree

- **Reported by**: slicer (`ws/slicer`, SLC-22, on top of `adbf10c`)
- **Affects**: release — `docs/adr/0005-slicer-glb-export-coordinates-and-node-ids.md` Decision 6,
  `docs/requirements.md` FR-05, `docs/architecture.md` §8 (T7)
- **Severity**: medium (privacy: decides whether geometry the presenter hid leaves the PC)
- **Milestone**: M1
- **Protocol**: v1.0 §7.3, §8 (unchanged either way)
- **Status**: open

## Steps to reproduce

1. Read FR-05: "The module exports **visible** model nodes …".
2. Read ADR 0005 Decision 6: "Invisible nodes are exported with `visible: false` in the state message rather than
   omitted, so toggling needs no re-export."
3. Read the SLC-07 follow-up in `docs/plan/slicer.md` ("decision for SLC-22 … ask `release`").

## Expected

One rule for models the 3D view does not show.

## Actual

The two documents disagree. SLC-22 implements the **privacy default**: a model leaves the PC only if a 3D view shows it
(`remoteview_core/mrml_scene.py`, `docs/research/slicer-scene.md` §1), and the consent text says "the surface meshes
of the models shown in the 3D view". Reason: a presenter often hides exactly the model that should not be shared — a
skin surface reconstructed from CT shows the patient's face (T7, NFR-16); with Decision 6 every viewer would receive it
as `visible: false` and could display it.

## Notes / suspected cause

Cost of the default: showing a hidden model during a session is a new node for the viewers, i.e. a full snapshot
(architecture §6 step 3 already treats a new node so) instead of a `scene.update{visible:true}`; hiding a shown model
stays a cheap `scene.update`. Please confirm the default and amend ADR 0005 Decision 6 (e.g. "models the 3D view does
not show are not exported; hiding is a `scene.update`, showing a hidden model re-exports"), or choose Decision 6 —
then SLC-22's `visible_model_nodes()` keeps hidden models (one condition) and the consent text must say that hidden
models are sent too.

The same question covers two cases Slicer's own display rules count as shown (`docs/research/slicer-scene.md`): a model
at effective opacity 0 (its own opacity or a folder's) and the parts of a model that clipping hides. SLC-22 exports both
whole, like the 3D view's rules (the consent text says "clipping is not applied"); leaving out opacity ≤ 0 would be one
more condition in `mrml_scene.py`. Please decide one rule for "not shown" (eye closed, hidden folder, opacity ≤ 0).
