# NFR-30: "a link of at most 64 characters fits QR version ≤ 4 at error level M" is off by two characters

- **Reported by**: slicer (`ws/slicer`, SLC-11, on top of `e7c29b7`)
- **Affects**: release — `docs/requirements.md` NFR-30 (and the SLC-11 row of `docs/plan/slicer.md`, which said "version ≤ 3")
- **Severity**: low
- **Milestone**: M2
- **Protocol**: none (the join link `https://<host>/j#<CODE>` of §10 is unchanged)
- **Status**: open

## Steps to reproduce

1. `segno.make("https://" + "h" * N + "/j#7KQ4X", error="m", micro=False, boost_error=False).version` for links of
   N + 16 = 33, 42, 43, 58, 62, 63, 64, 84, 85 characters.

## Expected

NFR-30: "encodes a deep-link URL <= 64 characters (fits QR version <= 4 at error level M)".

## Actual

Byte-mode capacity at level M is 14, 26, 42, **62**, 84 bytes for versions 1–5: links of 33–42 characters are version 3,
43–62 version 4, **63–64 version 5**, 65–84 version 5 as well (85 → version 6). Measured with segno 1.6.6: 62 → 4, 63 → 5.

## Notes / suspected cause

`remoteview_core/links.py` enforces the 64-character limit as written; a 64-character link is a version 5 code (37 modules + a
4-module quiet zone = 45 → 6 px per module at 270 px), which stock cameras read — `tests/test_links.py` decodes the codes with
zxing-cpp. Please either change the parenthesis to "version ≤ 5" or the limit to 62 (then only a host of up to 46 characters
works; a 42-character host such as a Railway `<service>-production.up.railway.app` name gives a 58-character link — the real
production host is `[TODO verify]` with DEP-07). A related open point for `deploy`/`release`: the link uses the relay's own host
(ADR 0006); a separate viewer domain would need a setting or a relay-announced base URL (`[TODO verify]`, DEP-07).
