# T6: the copied join link (and so the session code) stays on the system clipboard after the session ends

- **Reported by**: slicer (`ws/slicer`, SLC-11, on top of `e7c29b7`)
- **Affects**: release — `docs/architecture.md` §8, row T6 (leakage via logs, URL paths, fragments, Referer)
- **Severity**: low
- **Milestone**: M2
- **Protocol**: none
- **Status**: open

## Steps to reproduce

1. Start a session, click *Copy link* (FR-04), stop the session.
2. Paste anywhere.

## Expected

T6 lists every place the session code can outlive the session.

## Actual

The clipboard still holds `https://<host>/j#<CODE>`; the button's tooltip says so ("It stays on the clipboard until you copy
something else"). Clipboard history (Windows), cloud clipboard sync or a remote-desktop clipboard can carry it further. The
code expires with the session (NFR-11), so this is a residual risk rather than a leak.

## Notes / suspected cause

Please add the clipboard to T6's list, or decide that RemoteView should clear the clipboard when its session ends if it still
holds exactly that session's link (clipboard history keeps its copy either way).
