- **Protocol**: v1.1 §7.2, §7.3, §8.1, §9.1, §6.2, §3.3 (`docs/research/protocol-v1.1-decisions.md`, decisions D1–D3 and Annex A)
- **Status**: open

## Please implement

1. **Segment alias (reports 2026-10-19-slicer-3 and 2026-10-18-slicer-3; SLC-07/SLC-27).** `nodeId` of a segment is
   `<segmentationNodeID>/<segmentID>`, **except** when the segment ID is outside `[A-Za-z0-9_./:-]`, when the
   resulting `nodeId` is longer than 128 characters, or when `anonymizedNames` is true: then
   `<segmentationNodeID>/s_<n>` with `n` from a per-session counter that skips any value equal to a real segment ID of
   that segmentation. The alias is fixed for the scene's lifetime; keep a `raw ID → alias` map next to `SentScene` so
   SLC-30 updates and later snapshots reuse it. `extras.segmentId` carries the raw ID, or is omitted under
   `anonymizedNames`. Relax `_validate_identity` accordingly and reject a verbatim segment ID when names are
   hidden; remove the skip-and-report path. Tests: `"left lung"`, `"Läsion"`, `"Tumor(1)"`, a 110-character ID, an
   anonymised scene (no raw ID anywhere in the GLB JSON), a real segment called `s_1` (the namespace `s_<digits>` is reserved: such a raw ID is itself aliased), a model whose ID does not match `^vtkMRML[A-Za-z]+Node[0-9]+$` (alias `m_<n>`), and switching `anonymizedNames` on mid-session (a new snapshot must follow). The shared fixture
   `aliased-segments.glb` arrives with PRO-23.
2. **Shear (report 2026-10-18-slicer-4).** Already your behaviour (SLC-13). The text now defines TRS-decomposable as
   affine, non-zero finite scale, column axes whose pairwise cosine is at most 1e-6 (§7.2; a mirror is
   decomposable); your `coords.is_trs_decomposable` already matches. `baked: true` now means "world transform
   applied to the vertices (non-linear, shear, degenerate scale)".
3. **Pong deadline while uploading (report 2026-10-20-slicer-6; SLC-26).** Decided: `deadline = 10 s + min(60 s,
   B / 125,000 B/s)`, so at most 70 s (SLC-26's cap of 8 MiB gives 77 s: lower it to a 60 s extension); `B` =
   bytes written before the outstanding `ping` minus what a 1 Mbit/s uplink has moved since (your current
   formula); idle connections keep 10 s. Also: keep `B` at or below 4 MiB (Stop then reaches the relay within ≈ 35 s
   on 1 Mbit/s; the deadline is then ≤ ≈ 44 s) and send an extra `ping` out of cycle, for example after every 4 MiB
   written, so that a fast uplink is not throttled to 4 MiB per 15 s. Amend
   ADR 0009 Decision 4 via `release` (report 2026-10-27-protocol-4).
4. **Smaller contract points.** Name length ≤ 64 **UTF-16 code units** (Python `len` counts code points: count
   `len(s.encode("utf-16-le")) // 2`) — report 2026-10-19-slicer-5. `begin.sceneVersion`/`profile` must equal the GLB
   root `extras` and `nodeCount`/`triangleCount` are defined (§6.2) — report 2026-10-19-slicer-4; check it in
   `ProtocolClient.begin_snapshot`. `error PAYLOAD_TOO_LARGE{maxSnapshotBytes}` on `begin`: show "scene too large for
   this relay, reduce the profile". `SLOW_CONSUMER`/`4010` on the publisher = a drop (backoff, then
   `session.resume`).
5. **Version and vendoring (PRO-22).** `PROTOCOL_VERSION` becomes `"1.1"` in `shared/py`. After PRO-22 is on `main`,
   re-vendor: `node shared/scripts/vendor-py.mjs slicer-plugin/RemoteView/_vendor/remoteview_protocol` (until then
   `npm run check -w shared` reports the stale copy). Announce `"1.1"` once items 1–3 are implemented. PRO-24 (lazy
   `jsonschema` imports, `.gitattributes` for `shared/py`) will change the vendored files again; plan one more re-vendor.
