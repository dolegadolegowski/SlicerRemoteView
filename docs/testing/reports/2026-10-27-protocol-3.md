# Protocol 1.1: viewer-side rules (web, quest)

- **Reported by**: protocol (`ws/protocol`, on top of `3e6d04b`, PRO-20)
- **Affects**: web — `web-viewer/src/protocol/`, `src/render/`; quest — QST-05..QST-08 (not started)
- **Severity**: medium (silent desync and wrong pose are possible without these rules)
- **Milestone**: M3b
- **Protocol**: v1.1 §6.4, §6.5, §7.2, §7.3, §8.3, §9.1, §10 (`docs/research/protocol-v1.1-decisions.md`, Annex A)
- **Status**: open

## Viewer rules that are now part of the contract

1. **`ready` for the version being assembled (report 2026-10-20-server-3).** `scene.snapshot.ready` for the
   `sceneVersion` a viewer is assembling from the stream = discard the partial buffer, ignore later chunks of that
   version, fetch over HTTP. Test: begin → chunks → `ready` of the same version. A deferred viewer also gets an empty
   `scene.state` after `ready`.
2. **Liveness for the 10 s `pong` timeout (report 2026-10-20-server-6).** Count any inbound text or binary frame as
   life: close only after 10 s without any inbound data after a `ping` (snapshot chunks queue ahead of the `pong`).
3. **`scene.request` (report 2026-10-27-server-1).** The relay answers at most one per viewer per 5 s and ignores the
   rest silently: re-send an unanswered request after 5 s, once per gap. `haveSnapshotVersion` = the last snapshot
   version whose bytes were verified (hash OK). There is no streamed copy on request (§6.5).
4. **Cut download (report 2026-10-20-server-4).** A body shorter than `Content-Length` or a reset while the session
   lives is a failed download: drop the bytes, fetch the version of the latest `ready`/`viewer.joined`.
5. **TRS check (report 2026-10-18-slicer-4).** A node whose `matrix` is not TRS-decomposable (shear, zero or
   non-finite scale) is a malformed snapshot (§7.2): refuse it with the usual error screen, like the other §7.1
   pre-validation failures.
6. **Opaque `nodeId` (aliases, §7.3).** Never parse a `nodeId`; segment aliases look like `vtkMRMLSegmentationNode1/s_3`.
   Do not build DOM ids or URLs from it without escaping. Under `anonymizedNames: true` there is no `extras.segmentId`.
7. **Unknown message types** are ignored by clients (§2, only the relay answers `UNSUPPORTED_TYPE`).
8. **`/j?code=X`** answers 200 like `/j` (WEB-11 already strips the query).
