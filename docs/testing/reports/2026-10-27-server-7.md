# `/metrics`: gauges and memory figures beside the counters of §10 (SRV-19)

- **Reported by**: server (`ws/server`, SRV-19)
- **Affects**: protocol — `docs/protocol.md` §10 (`GET /metrics` row); deploy — DEP-05 (`docs/deploy.md`: what
  `/metrics` answers and holds); release — `docs/architecture.md` §8 (T6 residual of a leaked `METRICS_TOKEN`)
- **Severity**: low (wording; operator-only endpoint, behind `METRICS_TOKEN`)
- **Milestone**: M4
- **Protocol**: v1.0 §10
- **Status**: open

## Steps to reproduce

1. Start the relay with `METRICS_TOKEN` set (≥ 32 printable characters).
2. `curl -H "Authorization: Bearer $METRICS_TOKEN" https://<relay>/metrics`.

## Expected (protocol v1.0)

§10: "Prometheus text format; `404` when `METRICS_TOKEN` is unset (endpoint disabled). Counters only (sessions,
viewers, bytes, errors by code)".

## Actual (relay behaviour, by design — `relay-server/src/metrics.ts`, SRV-19 as planned)

1. Counters: `bytes_relayed_total`, `join_failures_total`, `ratelimit_hits_total{limit}`, `reconnects_total{role}`,
   `errors_total{code}`, and `codes_evicted_total` (codes the full quarantine released early, SRV-03 note).
2. Gauges as well: `sessions_active`, `viewers_active`, `snapshot_bytes_cached`, `buffered_bytes`,
   `heap_size_limit_bytes`, `process_resident_memory_bytes` (the plan's SRV-19 list; NFR-36 asks for active sessions
   and viewers and snapshot sizes, which are levels, not counts, and SRV-18 put the memory figures here rather than on
   `/healthz`).
3. Labels only from fixed sets (error codes, limit names, roles); no per-session, code, token or address label.
4. No or another token → `401 {"error":"UNAUTHORIZED"}` with `WWW-Authenticate: Bearer` (§10 names no answer).

## Notes / suggested change

- Protocol §10, `/metrics` row: "Prometheus text format (0.0.4); `404` when `METRICS_TOKEN` is unset (endpoint
  disabled), `401` without the right bearer token. Relay-wide counters and gauges only — sessions, viewers, bytes,
  failed joins, rate-limit hits, reconnects, errors by code, quarantine evictions, memory; no label carries a session,
  code, token or address."
- The plan's `buffered_bytes_total` is exposed as `buffered_bytes`: it is a gauge, and Prometheus reserves the `_total`
  suffix for counters.
- Deploy (DEP-05): `docs/deploy.md` could list the `404`/`401` behaviour and the metrics (relay README, "HTTP
  endpoints"), and say that `METRICS_TOKEN` is rotated by redeploying with a new value.
- Architecture §8 (T6 residual, release): a leaked `METRICS_TOKEN` exposes relay-wide aggregates only — no code,
  session, token or address — but they include how close failed joins are to the global alarm (§12) and whether the
  quarantine overflowed (codes reissued early, T1 residual); with few sessions live they come close to per-session
  figures (cached scene size, viewer counts and transfer activity over time) and show the headroom under the buffer,
  snapshot and heap budgets (timing a `CAPACITY` attack, T3). `/healthz` already shows the session count.
