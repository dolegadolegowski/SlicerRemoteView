# `/healthz` reports a relay-wide viewer total: architecture §8/§9, FR-28, NFR-38 and ADR 0006 wording (SRV-31)

- **Reported by**: server (`ws/server`, SRV-31)
- **Affects**: release — `docs/architecture.md` §9 (healthcheck body) and §8 (T6 residual risk); `docs/requirements.md`
  FR-28 ("exposes `/healthz` without session data") and NFR-38 ("returns 2xx within 100 ms without touching session
  data"); `docs/adr/0006-viewer-hosting-same-origin-as-relay.md` (Follow-ups, `server`: "`/healthz` without session
  data")
- **Severity**: low (documentation; the owner asked for the figure)
- **Milestone**: M4
- **Protocol**: v1.1 rev 2026-10-28, §10 (PRO-26)
- **Status**: open

## Steps to reproduce

1. Start the relay with a session that has viewers (or two sessions).
2. `curl https://<relay>/healthz` — no code, token or header needed.

## Expected (architecture §9, FR-28, NFR-38, ADR 0006)

`200 {status, uptimeS, sessions, version}`; FR-28 and ADR 0006: "without session data"; NFR-38: "within 100 ms
without touching session data".

## Actual (by design since SRV-31, owner's request 2026-10-28)

`200 {"status":"ok","uptimeS":1234,"sessions":3,"viewers":12,"version":"0.3.0"}` (and the same keys with `503` while
draining): `viewers` is the number of viewer sockets open across all sessions, the figure `/metrics` already had as
`viewers_active` behind `METRICS_TOKEN` (SRV-19, report `2026-10-27-server-7`). The web viewer's home page shows both
counts (WEB-24) and reads them every 30 s while it is open on the code entry.

## Notes / suggested change

1. Architecture §9, healthcheck: `GET /healthz` → `200 {status, uptimeS, sessions, viewers, version}`.
2. Architecture §8, T6 (or T1) residual risk — the sentence used in protocol §10, the relay README and SRV-31:
   relay-wide totals, readable without a code; no codes, IPs, session ids or tokens. With a single live session they
   are that session's viewer count over time; anyone who knows the counts of all sessions but one (a viewer or the
   presenter of each, from `viewer.count`) can work out the last one's, and changes over time hint at which session
   gained or lost viewers — accepted by the owner, 2026-10-28. `viewers` gives no help in guessing a code (`sessions`
   was already public, and a join attempt already tells the guesser whether a code is live). Before, viewer counts
   needed a code (`viewer.count`) or `METRICS_TOKEN`. Each home page left open adds one line to the Railway edge log
   every 30 s (IP and User-Agent, as for any request, §10); the relay itself does not log the read.
3. FR-28 and ADR 0006 (Follow-ups, `server`): "without session data" — reword to "relay-wide totals only: no codes,
   tokens, IPs, scene data or session ids" (an erratum or a superseding note for the ADR, as release prefers).
4. NFR-38 (operability): `/healthz` now reads each live session's viewer count (at most `MAX_SESSIONS` in-memory
   additions; no per-session data in the answer) and stays within the 100 ms (`test/app.test.ts`). Suggested wording:
   "returns 2xx within 100 ms; reads only in-memory relay-wide counts (no per-session data in the response)".
