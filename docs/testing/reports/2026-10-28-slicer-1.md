# Segments: hidden segments left out, `Opacity3D ≤ 0` as "not shown", geometry read-only, four-factor opacity (ADR 0005 Decisions 2 and 6)

- **Reported by**: slicer (`ws/slicer-segments`, SLC-35, on top of `f78e1b7`)
- **Affects**: release — `docs/adr/0005-slicer-glb-export-coordinates-and-node-ids.md` Decision 2 (geometry source),
  Decision 6 (`visible: false`, "segment opacity × segmentation `Opacity3D`") and its Follow-ups
  (`Opacity3D × SegmentOpacity3D` `[TODO verify]`); `docs/requirements.md` FR-05; extends `2026-10-20-slicer-5`
- **Severity**: medium (privacy: decides whether geometry the presenter hid leaves the PC; ADR text no longer matches
  the implementation)
- **Milestone**: M2
- **Protocol**: v1.1 §7.3 (unchanged either way: `visible`, `opacity`, `baked` keep their meaning)
- **Status**: open

## Steps to reproduce

1. Read ADR 0005 Decision 2: segments via `CreateClosedSurfaceRepresentation()` +
   `GetSegmentClosedSurfaceRepresentation(..., applyParentTransform=True)`.
2. Read ADR 0005 Decision 6: `alphaMode: "BLEND"` when "effective opacity < 1 (segment opacity × segmentation
   `Opacity3D`)"; "Invisible nodes are exported with `visible: false` … rather than omitted".
3. Read `2026-10-20-slicer-5` (hidden **models** are left out — the privacy default SLC-22 chose; open).
4. Read `slicer-plugin/RemoteView/remoteview_core/mrml_scene.py` (SLC-35) and Slicer v5.12.4
   `Modules/Loadable/Segmentations/MRMLDM/vtkMRMLSegmentationsDisplayableManager3D.cxx`
   (<https://github.com/Slicer/Slicer/blob/v5.12.4/Modules/Loadable/Segmentations/MRMLDM/vtkMRMLSegmentationsDisplayableManager3D.cxx>),
   `vtkInternal::IsVisible` and `vtkInternal::UpdateDisplayNodePipeline`.

## Expected

One rule for segments the 3D view does not show, and an ADR that describes the geometry source and the opacity the
exporter really uses.

## Actual

SLC-35 implements, for segments, exactly what the segmentations displayable manager reads when it draws a 3D view —
and that differs from ADR 0005 in four points:

1. **Hidden segments are left out** (not exported with `visible: false`): the privacy default of `2026-10-20-slicer-5`
   extended to segments while that report is open. A segment is exported only if `GetSegmentVisibility(id)` and
   `GetSegmentVisibility3D(id)` hold and the whole segmentation is drawn. The reason is the same as for models: a
   presenter often hides exactly the segment that should not be shared (a skin segment shows the patient's face;
   T7, NFR-16). **Cost**: a segment hidden at export time and shown later is a new node for the viewers → a full
   snapshot of the scene; a segment hidden after the export is a cheap `scene.update{visible: false}`. In Segment
   Editor workflows (segments toggled while presenting) this means more snapshots than Decision 6 would give.
2. **`Opacity3D ≤ 0` hides the whole segmentation.** `vtkInternal::IsVisible` returns false when
   `displayNode->GetOpacity3D() <= 0.0` (besides `GetVisibility()`, `GetVisibility3D()`, the view check and the
   folder hierarchy), so Slicer draws nothing for such a segmentation and the exporter sends nothing — **unlike a
   model**, which Slicer draws (invisibly) at opacity 0 and the exporter therefore sends whole (`2026-10-20-slicer-5`
   asked `release` to decide "not shown" for models too; the two kinds now differ at opacity 0, as Slicer's own
   displayable managers do).
3. **Geometry is read, never created** (Decision 2 deviation). `polydata(segment) =
   node.GetSegmentation().GetSegmentRepresentation(id, display.GetDisplayRepresentationName3D())` — the live polydata
   the DM draws; the collector makes its own geometry-only copy, and the parent transform is applied like a model's
   (SLC-13: `T.matrix` when linear, baked otherwise), not by `applyParentTransform=True`. The exporter never calls
   `CreateClosedSurfaceRepresentation()`/`CreateRepresentation()`: they write MRML, fire
   `RepresentationModified`/`ContainedRepresentationNamesModified` on the user's node and take seconds to minutes on
   whole-body data (ADR 0005 Consequences). The DM has already created the representation for everything it draws.
   Consequences: a segmentation with *Show 3D* off (`GetDisplayRepresentationName3D() == ""`) is not exported at all
   (the plan's criterion needs *Show 3D* on); a planar-contour 3D representation (SlicerRT polylines) or an empty one
   is reported as `no-triangles` and the rest of the scene ships.
4. **Four opacity factors, and an ungated colour override** (Decision 6 said two factors). `UpdateDisplayNodePipeline`
   sets the actor's opacity to `hierarchyOpacity × GetSegmentOpacity3D(id) × GetOpacity3D() ×
   genericDisplayNode->GetOpacity()`, where `genericDisplayNode` is the overriding folder display node when
   `GetFolderDisplayOverrideAllowed()` and such a node exists, else the segmentation display node — so a folder's
   opacity can enter twice (once as the hierarchy opacity, once as the generic node's). The exporter copies this;
   whether the double count is what the screen shows is `[TODO verify]` in manual §13 step 6 (SLC-37). The colour
   branch (`if (overrideHierarchyDisplayNode) … GetColor()`) is **not** gated by `GetFolderDisplayOverrideAllowed`,
   unlike the opacity and visibility branches; the exporter applies the folder colour whenever an overriding folder
   display node exists, and keeps the model adapter's gated reading for models (the model DM differs).

## Notes / suspected cause

Please (a) confirm or reverse the privacy default for **both** kinds (models: `2026-10-20-slicer-5`; segments:
this report) — reversing it means one condition fewer in `mrml_scene.py` per kind and a consent text that says hidden
models and segments are sent too; (b) decide whether a model at opacity 0 should follow the segmentation rule (not
shown) or stay exported; (c) add ADR 0005 errata for Decision 2 (geometry source: the DM's representation, read-only;
no `CreateClosedSurfaceRepresentation`, no `applyParentTransform` — the transform is SLC-13's) and Decision 6 (four
factors; hidden nodes left out, or not, per (a)), and close the ADR's Follow-up `Opacity3D × SegmentOpacity3D
[TODO verify]` once §13 step 6 has a result. The `slicer` plan rows SLC-35 and SLC-36 state the rule and its cost;
`docs/research/slicer.md` §2 keeps the ADR-era description and will be amended by `slicer` (rule 4) once `release`
has answered.
