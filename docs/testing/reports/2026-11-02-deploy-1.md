# `npm audit --omit=dev`: 4 vulnerable packages (6 moderate advisories) in the relay's production dependencies

- **Reported by**: deploy (`ws/deploy`, DEP-09 `audit` job, on top of `d70c5be`)
- **Affects**: server — `relay-server/package.json` (`fastify`, `@fastify/static`) and `package-lock.json`;
  protocol — `shared/` (`ajv` → `fast-uri`, used at run time by the relay through `@slicerremoteview/shared`)
- **Severity**: low (moderate advisories; no known exploit path checked against the relay's use — see notes)
- **Milestone**: M1
- **Protocol**: —
- **Status**: open

## Steps to reproduce

1. At the repository root on `main` (`d70c5be`): `npm ci`, then `npm audit --omit=dev`.

## Expected

No known vulnerability in the production dependency tree of the relay image (threat model T12).

## Actual

`4 moderate severity vulnerabilities` (npm 10.9, 2026-11-02): 4 vulnerable packages, 6 distinct advisories.

| Package (installed) | Path | Advisories | `npm audit` fix |

## Notes / suspected cause

- `fast-uri`: an in-range patch exists; `npm audit fix` (without `--force`) updates the lockfile only. A lockfile
  change redeploys the relay when merged to `main` — merge it when no session is running.
- `glob`/`minimatch` under `@fastify/static`: the relay serves a fixed `public/` tree; whether the advisories
  (AbortSignal cancellation, pattern handling) are reachable from requests is for `server` to judge. Track an
  `@fastify/static` release that depends on `glob` ≥ 14.0.2 / `minimatch` ≥ 11.0.1, or record an accepted risk.
- The CI `audit` job (`.github/workflows/ci.yml`) reports this on every run without blocking; it turns green once
  these are resolved or accepted. `pip-audit` finds nothing in `slicer-plugin/requirements-dev.txt` or `shared/py`.
