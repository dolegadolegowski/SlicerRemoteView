# `docs/testing/web.md` has no manual step for parts of US-06, US-07, US-08, US-10, US-11 and US-13

- **Reported by**: qa (`ws/qa`, commit `9cfa302`, QA-10)
- **Affects**: web — `docs/testing/web.md` (manual device scenarios; the steps are `web`'s, `CLAUDE.md` rule 4)
- **Severity**: low (manual test coverage; no product defect found)
- **Milestone**: M2
- **Protocol**: none
- **Status**: open

## Steps to reproduce

1. Open `docs/testing/web.md` §Scenario index → "User stories US-06…US-13 by device class" (added by QA-10).
2. Compare each acceptance criterion of US-06…US-13 in `docs/requirements.md` with the steps the table maps to it.

## Expected

QA-10 acceptance criterion 2 (`docs/plan/qa.md`): the `web.md` scenarios cover US-06…US-13 on the three device
classes (iPhone Safari, Android Chrome, Quest Browser) with result tables.

## Actual

Result tables now exist for every scenario (QA-10), but these criteria have no step on the device classes named:

1. **US-13, all three classes**: a well-formed but unknown code (viewer string "Code not recognised", code kept in
   the cells, input focused — US-13 criterion 1) and the rate-limit message after repeated failed joins ("Too many
   attempts", US-13 criterion 3, FR-44). Covered today: characters outside the alphabet (`W03` step 5), a wrong code in
   a link (`W02` steps 3–4), an ended session (`W11` steps 5–6).
2. **US-11, iPhone and Android**: the first join to a publisher that is connected but has not shared a scene yet
   ("Waiting for the presenter", US-11 criterion 2); only the relay-restart case (`W11` step 4) is covered.
3. **Quest Browser (2D page)**: §Quest Browser does not say to run the iPhone Safari scenarios, and its own steps do
   not check code entry (US-06 criterion 1) or the join time, opening a `/j#<CODE>` link (fragment removed, invalid
   fragment — US-07 criteria 2–3; the QR scan itself is not applicable in the headset), idle rendering (US-08
   criterion 3), depth sorting of a faded node (US-10 criterion 2), or a late join (US-11).

## Notes / suspected cause

The scenarios were written per task (WEB-03…WEB-25), not per user story. Suggested fix for `web`: add steps (or one
line in §Quest Browser saying which iPhone scenarios also run in the headset's 2D page) — QA-10 cannot write steps.
When fixed, update the coverage table in §Scenario index (`qa`). QA-11 (M3a) reorganises §Quest Browser and can
take item 3 into account.
