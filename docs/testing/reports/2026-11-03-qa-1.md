# Production dependencies carry 4 moderate npm advisories; `fast-uri` has an in-range fix

- **Reported by**: qa (`ws/qa`, commit `3df6e7e`, QA-09)
- **Affects**: server — root `package-lock.json` (`fast-uri` via `fastify` and `shared` → `ajv`; `@fastify/static` → `glob` → `minimatch`)
- **Severity**: low (no high or critical; the triggers are not reachable from a request, see the notes)
- **Milestone**: M2
- **Protocol**: none
- **Status**: open

## Steps to reproduce

1. At the repository root on `main` (`d70c5be`): `npm ci`, then `npm audit --omit=dev`.

## Expected

No known advisory in what ships in the relay image (T12, `docs/security.md` §5), or each one accepted with a
reason.

## Actual

4 moderate, 0 high, 0 critical (2026-11-02):

- `fast-uri` 4.2.2 and 3.1.8 — four advisories (GHSA-w74x-v6f9-j3xg, GHSA-xhq7-xmqj-769h, GHSA-wjr9-j795-jxcr,
  GHSA-333x-w4r6-6crp), fixed in 4.2.3 / 3.1.9, **within the semver range** (`fixAvailable: true`).
- `glob` 13.0.6 (GHSA-3g3m-2fjr-6pw4) and `minimatch` 10.2.6 (GHSA-g3hv-75wg-m249) via `@fastify/static` 10.1.6
  (direct dependency of `relay-server`); no fixed `@fastify/static` release yet (npm proposes a semver-major
  downgrade).

## Notes / suspected cause

Details and exposure assessment: `docs/research/qa-dependency-audit-2026-11-02.md`. Suggested: refresh the
lockfile for `fast-uri` (lockfile-only change); pin-bump `@fastify/static` once it depends on a fixed `glob`
(Dependabot, DEP-09). `@fastify/static` runs its glob once at start-up over `public/assets` with a fixed pattern,
and no shared schema uses `"format": "uri"`, so neither trigger is reachable from client input today.
