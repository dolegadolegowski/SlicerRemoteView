# CI skips the slicer job when only the root `CMakeLists.txt` or `LICENSE` changes

- **Reported by**: slicer (`ws/slicer-extensions-index`, SLC-72, on top of `9a9d4fc`)
- **Affects**: deploy — `.github/scripts/detect-changes.mjs` (the `python_slicer` job's `paths`)
- **Severity**: medium (only the full run after a merge to `main` checks the extension's metadata)
- **Milestone**: M4
- **Protocol**: —
- **Status**: open

## Steps to reproduce

1. On `ws/slicer-extensions-index` (SLC-72, ADR 0010), change only the root `CMakeLists.txt` — e.g. put a
   space before the closing parenthesis of `set(EXTENSION_SCREENSHOTURLS "…")`, which the Extensions Index CI
   then no longer finds.
2. Push the branch or open a pull request and read the `detect` job's decision.

## Expected

`python_slicer=true`: since SLC-72 the root `CMakeLists.txt` is the Slicer extension's top level (the only
copy of its metadata) and the root `LICENSE` its licence file; `slicer-plugin/tests/test_package.py` and
`test_skeleton.py` check both. Once the extension is in the Extensions Index, the Slicer factory builds `main`
every day.

## Actual

`python_slicer=false`: its `paths` are `slicer-plugin/`, `shared/`, `tools/fake-slicer/`, `package.json` and
`package-lock.json` (`detect-changes.mjs` L37–40), so those tests run only in the full run after the merge.

## Notes / suspected cause

Add `"CMakeLists.txt"` and `"LICENSE"` to `python_slicer.paths`: like `package.json`, an entry without a
trailing `/` matches that root file only (L78). Wanted before the index pull requests
(`docs/release/extensions-index.md`).
