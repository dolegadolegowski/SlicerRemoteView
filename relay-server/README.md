# relay-server — session codes, WebSocket relay, static web-viewer hosting (Node.js 22 / Fastify / ws)

Part of **SlicerRemoteView**. Owned by the `server` workstream (branch `ws/server`, plan
`docs/plan/server.md`). Contract: `docs/protocol.md`. Rules: `CLAUDE.md`.

## Purpose

The relay accepts one 3D Slicer publisher per session, hands out a 5-character session code, lets up to 20
viewers (web-viewer, Quest) join with it and forwards the scene to them. Everything is held in memory only
(single replica); nothing is written to disk and codes, tokens and scene bytes never reach a log. Design:
`docs/architecture.md` §3–§5, §8–§9; task list: `docs/plan/server.md`.

## How to run

From the repository root (Node 22, `npm ci` once):

```bash
npm run dev -w relay-server        # tsx watch, sources of shared/ via tsconfig paths, http://localhost:8787
npm run build                      # shared/ first, then relay-server/dist (and the other workspaces)
npm start -w relay-server          # node dist/index.js (needs the build above)
```

The relay listens on `0.0.0.0:$PORT`. For local work with the Vite dev server, allow its origin and turn off
proxy trust (nothing sets `X-Forwarded-For` locally):

```bash
ALLOWED_ORIGINS=http://localhost:5173 TRUST_PROXY=false npm run dev -w relay-server
cp relay-server/.env.example relay-server/.env    # or keep settings in a git-ignored .env …
node --env-file=relay-server/.env relay-server/dist/index.js   # … and load it with Node's --env-file
```

## Configuration

Environment variables (`src/config.ts`, same names as `docs/architecture.md` §9). Every value is validated at
start-up; an invalid one stops the process with exit code 1 and a `fatal` log line naming the variable (never
its value). Empty values count as unset. `relay-server/.env.example` lists exactly these variables with their
defaults (a test keeps both in sync).

| Variable                              | Default                            | Meaning                                                                                                                                                                                                                          |
| ------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PORT`                                | `8787`                             | listen port (Railway injects it)                                                                                                                                                                                                 |
| `LOG_LEVEL`                           | `info`                             | `fatal`, `error`, `warn`, `info`, `debug`, `trace` or `silent`                                                                                                                                                                   |
| `METRICS_TOKEN`                       | unset                              | Bearer for `GET /metrics` (≥ 32 printable characters, e.g. `openssl rand -base64 32`); unset disables `/metrics`                                                                                                                 |
| `SESSION_TTL_S`                       | `1800`                             | idle TTL while a session has no connected viewers (§4.4); at most the protocol value                                                                                                                                             |
| `PUBLISHER_GRACE_S`                   | `120`                              | resume window after the publisher's socket is lost (§9.1); at most the protocol value                                                                                                                                            |
| `SESSION_MAX_LIFETIME_S`              | `43200`                            | hard cap on a session's lifetime; at most the protocol value                                                                                                                                                                     |
| `CODE_QUARANTINE_S`                   | `600`                              | a released code is not reissued for this long (ADR 0008); at least `60`                                                                                                                                                          |
| `MAX_SNAPSHOT_BYTES`                  | `67108864`                         | per-snapshot cap, at most the protocol maximum (64 MiB)                                                                                                                                                                          |
| `MAX_TOTAL_SNAPSHOT_BYTES`            | `536870912`                        | cached + in-flight snapshots of all sessions; ≥ 2 × `MAX_SNAPSHOT_BYTES`                                                                                                                                                         |
| `MAX_TOTAL_BUFFERED_BYTES`            | `167772160`                        | Σ of all viewer send buffers (≥ 8 MiB, the per-viewer hard watermark); slowest consumers closed `4010` above it                                                                                                                  |
| `MAX_VIEWERS`                         | `20`                               | viewers per session, at most the protocol maximum (20)                                                                                                                                                                           |
| `MAX_SESSIONS`                        | `100`                              | live sessions (`CAPACITY` beyond)                                                                                                                                                                                                |
| `ALLOWED_ORIGINS`                     | `https://${RAILWAY_PUBLIC_DOMAIN}` | comma-separated browser origins allowed on `/ws` (exact match, no wildcards, `http:` only for `localhost`/`127.0.0.1`/`[::1]`); without both, only clients that send no `Origin` (Slicer, Unity)                                 |
| `TRUST_PROXY`                         | `true`                             | client IP = the `X-Forwarded-For` entry added by the immediate peer (Railway edge), never a client-sent one; `false` = socket address (direct local access). `true` assumes the relay is reachable only through the Railway edge |
| `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` | `30`                               | SIGTERM → SIGKILL window for the `4008` drain on redeploy                                                                                                                                                                        |

The three session timers are protocol maximums (§3.3, §14): a relay may run shorter, never longer.
`RELAY_TEST_FAST_TIMERS` is test-only: it is honoured only under `NODE_ENV=test` (SRV-21) and never set in
deployments. `NODE_OPTIONS` (`--max-old-space-size-percentage=75`, architecture §9) is set by the Dockerfile
(SRV-20) and read by Node, not by `config.ts`; `RAILWAY_PUBLIC_DOMAIN` is injected by Railway.

## HTTP endpoints

| Endpoint            | Answer                                                                                                                                                                                                                                                                                                                                        |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /healthz`      | `200 {"status":"ok","uptimeS":…,"sessions":…,"version":"…"}` — no codes, IPs or memory figures                                                                                                                                                                                                                                                |
| `GET /api/version`  | `200 {"name":"slicer-remote-view-relay","version":…,"protocolVersions":["1.0"],"limits":{…}}` (§10)                                                                                                                                                                                                                                           |
| `GET`/`HEAD /api/scene/:sceneVersion` | the cached GLB for `Authorization: Bearer <viewerToken>` (§10): `200 model/gltf-binary` with `ETag`, `X-Scene-Version`, `Cache-Control: private, no-store`; `401` no or unknown token, `404` other version or any query string/fragment/encoding in the target, `410` session ended (≤ `CODE_QUARANTINE_S` ago), `429` above 30/min per token |
| `GET /ws` (Upgrade) | WebSocket for both roles (§3): more than 30 upgrades per minute from one client address → HTTP 429 `{"error":"RATE_LIMITED"}` with `Retry-After`; browser `Origin` must be in `ALLOWED_ORIGINS` (else HTTP 403), no `Origin` (Slicer, Unity) is fine; a `Sec-WebSocket-Protocol` offer is refused (HTTP 400); a plain HTTP `GET /ws` is a 404 |
| anything else       | `404 {"error":"NOT_FOUND"}` — no SPA fallback, the path is never echoed                                                                                                                                                                                                                                                                       |

`GET /api/version` announces the effective `MAX_SNAPSHOT_BYTES` and `MAX_VIEWERS` (§14).

Logs are JSON lines (`level`, `time`, `message`) on stdout; per-request logging is disabled.

## Design notes

| Module                 | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/config.ts`        | environment → validated `Config` (fail fast, protocol maximums)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `src/codes.ts`         | 5-symbol session codes (`crypto.randomInt` per symbol over `23456789ABCDEFGHJKMNPQRSTUVWXYZ`, redraw on collision), the release quarantine (`CODE_QUARANTINE_S`, bounded), `pt_`/`vt_` tokens (256 bit, base64url), SHA-256 storage and constant-time comparison                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `src/registry.ts`      | in-memory sessions (architecture §3): phases `allocated → active → grace → closed/expired`, code index, quarantine, TTL sweep every 10 s (grace `PUBLISHER_GRACE_S`, idle `SESSION_TTL_S` only while no viewer is connected, lifetime `SESSION_MAX_LIFETIME_S`), `MAX_SESSIONS` → `CAPACITY`, `expiring`/`expired`/`released` events; releasing a session drops its snapshot buffers — nothing is written to disk. Each session also holds its publisher `Peer` and its viewers (`Viewer{id, tokenHash, platform, joinedAt, peer}`; `addViewer` → `SESSION_FULL` at `MAX_VIEWERS` connected, disconnected entries kept for rejoin up to 3 × `MAX_VIEWERS`, viewer-token index by SHA-256 dropped with the session; the token hashes of an ended session are remembered for `CODE_QUARANTINE_S`, at most `MAX_SESSIONS` × 3 × `MAX_VIEWERS`, so `/api/scene` can answer `410`) and answers `ttl()` for `session.created`/`resumed`/`renewed`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `src/ratelimit.ts`     | per-client-address limits (§12, ADR 0008): keys are HMAC-SHA256 of the address under a per-boot secret (no raw IP in state or logs); an IPv6 address counts as its /64, IPv4-mapped/-translated/-compatible ones as IPv4, a `:port` suffix is dropped; sliding windows — upgrades 30/min (only upgrades that pass the Origin and subprotocol checks), `viewer.join{code}` 10/min (a right code gives its attempt back: classroom NAT), `session.create` 5/min; 20 failed joins in 10 min → 10 min ban (`retryAfterS` = time left; bans are kept apart from the key LRU — at most 20,000, the oldest ban dropped first at that cap); > 1,000 failed joins/h (minute buckets) → one `warn` (counts only) and 3 joins/min for an hour; idle keys swept every minute; at most 20,000 keys tracked, least recently used dropped first (≈ 27 MiB at the cap with every window full). A well-formed `preferredCode` counts as a failed join, granted or not (not on a `CAPACITY` refusal), and is ignored while the address is banned or, during the alarm, above 3/min. In memory only (reset on redeploy)                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `src/clock.ts`         | injectable time source; tests drive TTLs with `test/helpers/manual-clock.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `src/app.ts`           | Fastify factory: `/healthz`, `/api/version`, 404 handling, client-IP policy; starts/stops the registry sweep with the server. Builds the per-boot `RateLimiter` shared by the `/ws` upgrade hook and the publisher/viewer handlers and runs its sweep with the server. Wires the publisher handlers (create/close, publisher socket loss, expiry broadcast; the expiry listener is detached on close) the viewer handlers (code normaliser, join/leave, viewer socket loss; pending `INVALID_CODE` refusals are cancelled on close) the snapshot handlers (chunks, abort on publisher socket loss; chunk timeouts and the `released` listener disposed on close) the fan-out (`SnapshotEvents`, the `overCapacity` join hook, a watch every second; stopped in `preClose`, which also resumes paused publishers so their sockets read the shutdown close) and the `/api/scene` route with its download tracker (a cache swap ends the downloads of the old buffer).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `src/ws/endpoint.ts`   | `/ws` transport (§3): `maxPayload` 1 MiB + 64 KiB (`1009` before reading), no `permessage-deflate`, Origin check before the upgrade, upgrades offering a subprotocol refused with 400 (§3.1: nothing secret in `Sec-WebSocket-Protocol`), `4012` when no session is bound 10 s after the upgrade, text limits 256 KiB / 16 KiB (the first message gets the limit of the role its type fixes; `PAYLOAD_TOO_LARGE` + `1009`), binary only from the publisher of a bound session (`UNAUTHORIZED` + `1008`), upgrades to any other route refused with 404 before the upgrade, every hook guarded against throws and rejected promises (`INTERNAL` + `1011`, `replyTo` = the frame's `id`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `src/ws/frame.ts`      | each text frame is `JSON.parse`d exactly once (`readFrame`: value, peeked `type` and well-formed `id`); `checkEnvelope` applies `parseEnvelope`'s checks to the parsed value (a test compares both over every shared fixture)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `src/ws/dispatch.ts`   | every text frame through the `parseEnvelope` checks (shared, schemas compiled at start-up; a per-type `Normalizer` may rewrite the parsed object first, e.g. the `viewer.join` code): protocol major ≠ 1 → `UNSUPPORTED_VERSION` + `4000` (before the role gate, §2); first message fixes the role (`session.create`/`session.resume` → publisher, `viewer.join` → viewer, else `UNAUTHORIZED` + `1008`); a known type outside the role's §11 column → `UNAUTHORIZED` (before its schema is looked at); until a session is bound only handshake types and `ping` are accepted (anything else, unknown types included, is an `UNAUTHORIZED` offence), afterwards handshake types are; unknown type on a bound socket → `UNSUPPORTED_TYPE` (open); schema violation → `INVALID_MESSAGE{details.instancePath ≤ 128 chars}`; the third protocol violation (`INVALID_MESSAGE` or `BAD_SEQUENCE`) → `4007`; second `UNAUTHORIZED` → `1008`; `type → handler` table; `ping` → `pong`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `src/ws/publisher.ts`  | publisher lifecycle (§4): `session.create` → `session.created` (code, one-time `publisherToken`, `viewerLimit`, `ttl`, effective `limits`; `CAPACITY` + `4006` at `MAX_SESSIONS`; `RATE_LIMITED` + `4006` above 5/min per address); `session.close` → viewers get `session.closed{PUBLISHER_CLOSED}` + `4001`, publisher `1000`, code quarantined; publisher socket lost → grace + `session.publisherState{online:false, graceEndsAt}`; relay expiry → `session.expired{reason}` + `4002` to viewers and publisher                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `src/ws/viewer.ts`     | viewer join (§5): the code is normalised before validation (whitespace removed, upper case, §12); `RATE_LIMITED{retryAfterS}` + `4006` per client address before any lookup; malformed, unknown and quarantined codes all get `INVALID_CODE` + `4004` after a random 50–150 ms, the socket reading nothing more meanwhile; a live code → `viewer.joined` (one-time `viewerToken`) then `scene.state`; `SESSION_FULL` + `4005`, `CAPACITY` + `4006` while the viewers' send buffers hold `MAX_TOTAL_BUFFERED_BYTES` (`ws/fanout.ts`); `viewer.count{viewerCount, viewerLimit, platforms}` (documented platform names only) to publisher and viewers after every join and leave; `viewer.leave` (then `1000`) and drops keep the entry for rejoin                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `src/ws/snapshot.ts`   | snapshots (§6.1–§6.4). `scene.snapshot.begin` checks — `sceneVersion` a uint32 above every version used so far (`BAD_SEQUENCE`, which also discards a snapshot of that version in flight), `byteLength` above `MAX_SNAPSHOT_BYTES` → `PAYLOAD_TOO_LARGE` (also above the protocol maximum), `chunkCount = ceil(byteLength / chunkSize)` (`INVALID_MESSAGE`), cached + in-flight bytes of all sessions within `MAX_TOTAL_SNAPSHOT_BYTES` (`CAPACITY`, one `warn` per minute at most); a newer begin supersedes the snapshot in flight; the chunks of a refused version are ignored (a begin the schema rejects reserves nothing); one zero-filled buffer per snapshot, never pooled. Binary chunks above 1 MiB + 12 B → `PAYLOAD_TOO_LARGE` + `1009`, otherwise checked with `shared`'s `decodeChunkHeader`/`checkChunk` (`BAD_SEQUENCE{field}`, snapshot discarded, its later chunks ignored), copied in place and fed into a running SHA-256 — GLB content is never parsed. `end`: all chunks and the SHA-256 of `begin`/`end` match → the cache is swapped in one assignment (old buffer dropped), node state reset, session `active`, publisher gets `scene.snapshot.ack`; a missing chunk or another hash → `CHECKSUM_MISMATCH` and the buffer is freed. Aborts (`SUPERSEDED`, `BAD_SEQUENCE`, `CHECKSUM_MISMATCH`, the publisher's own, `PUBLISHER_GONE`, `TIMEOUT` after 120 s without a chunk — the publisher also gets `BAD_SEQUENCE{chunkIndex, timeoutS}`) go to `SnapshotEvents`, like the accepted `begin`, chunks and `end` (`ws/fanout.ts`) |
| `src/ws/fanout.ts`     | snapshot fan-out and viewer send buffers (§3.3, §6.4, §6.5, §9.3; architecture §4, §5). At an accepted `begin`, connected viewers whose `bufferedAmount` is below 4 MiB are streamed: the publisher's `begin`, chunks and `end` byte for byte, each chunk the same `Buffer` for every socket; the others, viewers that join mid-stream and streamed viewers at or above 4 MiB before a chunk get `scene.snapshot.ready` after `end` (the ack counts both). Aborts reach every viewer that got the `begin` (the publisher's own as received). `error SLOW_CONSUMER` + `4010` above 8 MiB, after more than 60 s at or above 4 MiB, or — largest buffer first, any session — when Σ `bufferedAmount` plus the next chunk would exceed `MAX_TOTAL_BUFFERED_BYTES` (a socket holding less than the chunk is not closed: a streamed one is deferred instead); a closed slow consumer whose client does not complete the close is terminated after 5 s. While the sum (sockets it closed included, until they are gone) is at or above the budget, a publisher whose snapshot is in flight and whose streamed viewers hold its chunks is not read (`ws` `pause()`), at most 5 s at a time and then read for at least a second, so its pings are answered within 10 s (§9.1); every other publisher keeps being read. Joins get `CAPACITY` while the live buffers (without those it closed) hold the budget. A failing watch is logged (`INTERNAL`, no text) and keeps running.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `src/http/scene.ts` | `GET`/`HEAD /api/scene/:sceneVersion` (§10, §6.5): a request target other than exactly `/api/scene/<canonical decimal>` (query string, fragment, percent-encoding, `01`) → `404 {"error":"NOT_FOUND"}` (nothing echoed); no `Authorization: Bearer <token>` (scheme case-insensitive) → `401` + `WWW-Authenticate: Bearer`; a token of a live viewer entry (connected or not) → at most 30 requests/min per token (`429` + `Retry-After`); the token of a session that ended less than `CODE_QUARANTINE_S` ago → `410`; any other → `401`; another version than the cached one → `404`; else `200 model/gltf-binary` from the cached `Buffer` (`Content-Length`, `ETag: "<sha256>"`, `X-Scene-Version`, `Cache-Control: private, no-store`), `HEAD` without the body. `sceneDownloads` ends a download when its `Buffer` leaves the cache (session end, newer snapshot) or after 60 s of inactivity on its connection (pipelined requests included), so no scene bytes outlive the snapshot budget. Logs: ids, versions, byte counts, error codes. |
| `src/ws/connection.ts` | one socket: role, envelope fields on send (`protocolVersion`, `ts`), `error` + close helpers, handshake timer, protocol-violation strikes (`violation()`: `INVALID_MESSAGE`/`BAD_SEQUENCE`, third → `4007`), `awaitClose()` (frames ignored and the handshake timer stopped while a final answer is pending), `forward()` of a publisher frame as received, `bufferedAmount`, `pauseReading()`/`resumeReading()` (a close resumes reading so the close handshake completes; a closing socket is not paused again), `terminate()`. Implements the registry's `Peer` and carries the bound `session` (and `viewer`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `src/logger.ts`        | pino JSON lines with redaction of codes and tokens                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

## Test and lint commands

```bash
npm test -w relay-server             # vitest (all relay tests)
npm test -w relay-server -- app      # one file by name filter, e.g. `app`, `config`, `codes`, `viewer`, `snapshot`, `fanout`, `http-scene`
npm run lint -w relay-server         # eslint + prettier --check
npm run typecheck -w relay-server
npm run build -w relay-server        # tsc → relay-server/dist (needs `npm run build -w shared` first)
```

The root `npm test`, `npm run lint`, `npm run typecheck`, `npm run build` run every workspace.

The per-address limits (`src/ratelimit.ts`) also apply to E2E and load tests: from one address, more than 30
upgrades, 10 wrong codes or 5 sessions per minute are refused, and 20 wrong codes within 10 minutes ban it. Harnesses run the relay with `TRUST_PROXY=true`
and give each simulated client its own `X-Forwarded-For` address, as `test/ratelimit.test.ts` does. The Docker image
(`docker build -f relay-server/Dockerfile .` from the repo root) arrives with SRV-20.
